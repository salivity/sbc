Implementing PWM LED Dimming on a Custom SBC

This guide outlines how developers can implement Pulse-Width Modulation (PWM) to control LED brightness on a custom Single Board Computer (SBC). It covers the essential hardware considerations, timer peripheral and register configuration, firmware-level duty cycle manipulation, and visual compensation techniques necessary for smooth and reliable dimming.

1. Hardware Pin Assignment and Circuit Design

To implement PWM dimming, identify a General-Purpose Input/Output (GPIO) pin on the custom SBC’s System on Chip (SoC) or microcontroller that is internally mapped to a hardware timer/counter peripheral with PWM generation capabilities.

  • Direct Drive (Low Power): If driving a single low-power indicator LED (typically under 15–20 mA), wire the PWM-capable GPIO through a current-limiting resistor to the LED anode, with the cathode connected to ground.
  • Transistor/MOSFET Drive (High Power): For high-brightness LEDs or LED strips drawing more current than the SoC pin can source, connect the GPIO pin to the gate of an N-channel logic-level MOSFET with a pull-down resistor to prevent floating states during board bootup.

2. Configuring the Hardware Timer Peripheral

Hardware PWM is preferred over software bit-banging to prevent CPU overhead and jitter.

  1. Select PWM Frequency: Set a frequency high enough to prevent visible flicker. For human vision, any frequency above 100 Hz works, but frequencies between 1 kHz and 20 kHz are standard to avoid audible switching noise from ceramic capacitors or inductors.
  2. Set the Prescaler and Period: Calculate the timer's clock prescaler and auto-reload register (ARR) / period register value based on the SoC’s master clock frequency: \[\text{PWM Frequency} = \frac{\text{Timer Clock}}{(\text{Prescaler} + 1) \times (\text{Period} + 1)}\]
  3. Define Resolution: The period value determines the dimming resolution. For instance, a period count of 255 yields 8-bit resolution (256 steps), while a count of 65535 yields 16-bit resolution.

3. Setting the Duty Cycle in Firmware

The duty cycle represents the ratio of the signal's "on" time to the total period time, determining the average power delivered to the LED.

  • Register-Level (Bare Metal / RTOS): Update the timer’s Capture/Compare Register (CCR) to adjust the duty cycle.
    • \(0\%\text{ Brightness} \rightarrow \text{CCR} = 0\)
    • \(50\%\text{ Brightness} \rightarrow \text{CCR} = \text{Period} / 2\)
    • \(100\%\text{ Brightness} \rightarrow \text{CCR} = \text{Period}\)
  • Linux-Based SBC (Device Tree & Sysfs):
    1. Define the PWM pin and peripheral within the Device Tree (.dts).
    2. Export the PWM channel via the Linux PWM subsystem: 
      echo 0 > /sys/class/pwm/pwmchip0/export
echo 1000000 > /sys/class/pwm/pwmchip0/pwm0/period    # 1 kHz (1,000,000 ns)
echo 500000 > /sys/class/pwm/pwmchip0/pwm0/duty_cycle # 50% duty cycle
echo 1 > /sys/class/pwm/pwmchip0/pwm0/enable

4. Applying Gamma Correction for Perceived Brightness

Human eye perception of light intensity is non-linear and follows an approximate power-law relationship (CIE 1931 lightness formula). If duty cycle increases linearly, the LED will appear to brighten rapidly at low values and change minimally at high values.

To achieve perceived linear dimming:

  1. Implement a gamma correction formula: \[\text{Duty Cycle} = \left(\frac{\text{Input Value}}{\text{Max Input}}\right)^\gamma \times \text{Max Duty}\] (A standard \(\gamma\) value between 2.0 and 2.8 works well for LEDs).
  2. Precompute a look-up table (LUT) containing gamma-corrected values to avoid running floating-point calculations during runtime.
