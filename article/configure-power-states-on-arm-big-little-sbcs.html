Configure Power States on ARM big.LITTLE SBCs

Configuring custom power management states on an ARM big.LITTLE single board computer (SBC) enables developers to optimize thermal efficiency, battery life, and processing throughput across asymmetric core clusters. This guide outlines how to define custom idle states and voltage-frequency pairs in the Linux Device Tree, configure the kernel for Energy Aware Scheduling (EAS), and adjust runtime power behavior using sysfs.

1. Defining Custom Idle States in the Device Tree

ARM power states (C-states) rely on the Power State Coordination Interface (PSCI) or custom CPU idle drivers. Idle states are declared in the Device Tree Source (.dts or .dtsi) files for the board.

Under the cpus node, define the idle-states container to declare custom latency and residency requirements:

cpus {
    idle-states {
        entry-method = "psci";

        CPU_RETENTION: cpu-retention {
            compatible = "arm,idle-state";
            arm,psci-suspend-param = <0x00000001>;
            entry-latency-us = <20>;
            exit-latency-us = <40>;
            min-residency-us = <100>;
        };

        CPU_POWER_DOWN: cpu-power-down {
            compatible = "arm,idle-state";
            arm,psci-suspend-param = <0x00010000>;
            entry-latency-us = <150>;
            exit-latency-us = <250>;
            min-residency-us = <1000>;
        };
    };
};

Bind these states to the specific big and LITTLE core nodes:

/* Assign to a LITTLE core (e.g., Cortex-A53/A55) */
cpu0: cpu@0 {
    device_type = "cpu";
    compatible = "arm,cortex-a53";
    cpu-idle-states = <&CPU_RETENTION &CPU_POWER_DOWN>;
};

/* Assign to a big core (e.g., Cortex-A72/A76) */
cpu4: cpu@100 {
    device_type = "cpu";
    compatible = "arm,cortex-a72";
    cpu-idle-states = <&CPU_POWER_DOWN>;
};

2. Setting Operating Performance Points (OPP)

Dynamic Voltage and Frequency Scaling (DVFS) manages active power states (P-states). Because big.LITTLE architectures use separate power rails and clock domains for each cluster, you must configure separate OPP tables for the LITTLE and big clusters:

opp_table_little: opp-table-0 {
    compatible = "operating-points-v2";
    opp-shared;

    opp-408000000 {
        opp-hz = /bits/ 64 <408000000>;
        opp-microvolt = <950000>;
        clock-latency-ns = <40000>;
    };
    opp-1416000000 {
        opp-hz = /bits/ 64 <1416000000>;
        opp-microvolt = <1150000>;
    };
};

opp_table_big: opp-table-1 {
    compatible = "operating-points-v2";
    opp-shared;

    opp-816000000 {
        opp-hz = /bits/ 64 <816000000>;
        opp-microvolt = <1000000>;
    };
    opp-2000000000 {
        opp-hz = /bits/ 64 <2000000000>;
        opp-microvolt = <1250000>;
    };
};

Reference the respective OPP tables under each CPU cluster definition using operating-points-v2 = <&opp_table_little>; and operating-points-v2 = <&opp_table_big>;.

3. Kernel Configuration

To utilize custom power states and coordinate asymmetric clusters, ensure the following options are enabled in your kernel .config:

  • CONFIG_CPU_IDLE=y — Enables the generic CPU idle framework.
  • CONFIG_ARM_CPUIDLE=y — Enables ARM-specific cpuidle drivers.
  • CONFIG_ARM_PSCI_CPUIDLE=y — Enables PSCI-based idle state execution.
  • CONFIG_CPU_FREQ=y — Enables the CPU frequency scaling framework.
  • CONFIG_ENERGY_AWARE_SCHEDULING=y — Directs tasks to the most energy-efficient core using the Energy Model.
  • CONFIG_CPU_FREQ_GOV_SCHEDUTIL=y — Integrates frequency scaling directly with the CFS scheduler.

Compile the kernel and Device Tree binaries (dtb), then deploy them to the SBC.

4. Runtime Inspection and Tuning via Sysfs

Once booted, interact with the sysfs interface to test and adjust custom states in real time.

Managing CPU Idle States

Inspect configured C-states on a specific core:

# List available idle states on core 0
ls /sys/devices/system/cpu/cpu0/cpuidle/

# View the name and residency time of state 1
cat /sys/devices/system/cpu/cpu0/cpuidle/state1/name
cat /sys/devices/system/cpu/cpu0/cpuidle/state1/residency

# Disable a specific idle state at runtime (1 = disabled, 0 = enabled)
echo 1 > /sys/devices/system/cpu/cpu0/cpuidle/state1/disable

Managing CPU Frequency and Governors

Set the governor to schedutil to enable Energy Aware Scheduling across the clusters:

# Set governor for the policy governing the LITTLE cluster
echo schedutil > /sys/devices/system/cpu/cpufreq/policy0/scaling_governor

# Set governor for the policy governing the big cluster
echo schedutil > /sys/devices/system/cpu/cpufreq/policy4/scaling_governor

Lock a cluster to a specific OPP state using the userspace governor for latency-critical benchmarking:

echo userspace > /sys/devices/system/cpu/cpufreq/policy4/scaling_governor
echo 1416000 > /sys/devices/system/cpu/cpufreq/policy4/scaling_setspeed
