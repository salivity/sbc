How to Route I2S Audio from an SBC to a DAC

This article explains how digital audio data is routed from a Single Board Computer (SBC) to an external Digital-to-Analog Converter (DAC) using the Integrated Inter-IC Sound (I2S) protocol. It details the essential physical connections, clock synchronization roles, operating system configurations, and the step-by-step data path from raw digital PCM audio to an analog signal.

What is the I2S Protocol?

Integrated Inter-IC Sound (I2S) is a synchronous serial communication protocol designed specifically for transferring digital audio data between integrated circuits. Unlike general-purpose buses like SPI or I2C, I2S separates clock and data signals to eliminate jitter and timing discrepancies that can degrade audio quality.

Physical Wiring and Signal Lines

To establish an I2S connection between an SBC (such as a Raspberry Pi or Rock Pi) and an external DAC, specific hardware pins must be connected:

  • Bit Clock (BCLK / SCK): Synchronizes individual data bits. Each audio bit transmitted across the data line corresponds to one cycle of BCLK.
  • Word Select / Left-Right Clock (WS / LRCLK): Determines whether the transmitted data belongs to the left or right audio channel. The frequency of LRCLK corresponds directly to the sample rate of the audio (e.g., 44.1 kHz or 48 kHz).
  • Serial Data Out (SDATA / DOUT): The line that carries the serialized Pulse Code Modulation (PCM) audio bits from the SBC to the DAC.
  • Master Clock (MCLK): An optional high-frequency reference clock (typically 128x, 256x, or 512x the sample rate) required by some DAC architectures to drive internal delta-sigma modulators. Many modern DACs generate this internally via Phase-Locked Loops (PLLs) if MCLK is not provided.
  • Ground (GND): A shared reference ground is required to maintain signal integrity and avoid ground loop noise.

Master and Slave Configurations

I2S systems rely on a defined relationship between the clock master and the clock slave:

  • SBC as Master: The SBC generates the BCLK and LRCLK signals using its internal crystal oscillators and sends both the clock signals and data to the DAC.
  • DAC as Master: The DAC board features high-precision dedicated oscillators that generate BCLK and LRCLK, sending them back to the SBC. The SBC acts as a slave, syncing its data output to the incoming clocks. This configuration provides lower jitter and superior audio quality.

Software Configuration and Driver Layer

Before data can flow over the hardware pins, the SBC operating system (typically Linux) must be configured:

  1. Device Tree Overlays (DTO): The SBC needs a device tree overlay enabled (via config files like config.txt or extlinux.conf) to map the generic GPIO pins to the processor's internal I2S controller.
  2. ALSA Driver: The Advanced Linux Sound Architecture (ALSA) loads a specific audio machine driver matching the DAC chip (e.g., PCM5102A, ES9038, or a generic i2s-mmap driver). This exposes the DAC as a valid output endpoint (hw:X,Y).

The End-to-End Routing Process

Once configured, the path of audio data follows these sequential steps:

  1. Audio Generation: An application (such as a media player) decodes an audio file into raw, uncompressed PCM data.
  2. ALSA Sound Subsystem: The application hands the PCM stream to ALSA, which handles bit depth, channel mapping, and sample rate conversion if needed.
  3. Direct Memory Access (DMA): The CPU transfers the PCM data buffers to the SBC's I2S controller memory via DMA without consuming excessive CPU cycles.
  4. Serialization: The I2S hardware controller reads the parallel PCM words from its FIFO buffer and serializes them into a single-bit stream.
  5. Transmission: The controller transmits the serialized bits across the SDATA line in sync with the BCLK, switching channels according to the LRCLK.
  6. Digital-to-Analog Conversion: The external DAC reads the data stream based on the clock edges, reconstructs the discrete digital values, and passes them through an internal low-pass reconstruction filter to produce the continuous analog audio waveform for speakers or headphones.
