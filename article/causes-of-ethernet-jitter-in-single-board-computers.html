Causes of Ethernet Jitter in Single Board Computers

Network jitter, defined as the statistical variation in packet transit delay, significantly impacts time-sensitive applications running on single board computers (SBCs) such as robotics, industrial automation, and real-time audio/video streaming. This article examines the primary hardware, operating system, driver, and network factors that introduce jitter over an SBC's Ethernet interface and provides a clear breakdown of why these variations occur.

1. Hardware Architecture and Bus Bottlenecks

The internal architecture of a single board computer plays a major role in packet transmission timing:

  • Ethernet Controller Implementation: Many budget or older SBCs do not have native Ethernet controllers connected directly to the system bus (like PCIe). Instead, they route Ethernet traffic through an internal USB bus (USB-to-LAN bridges). This adds USB protocol overhead, packet serialization delays, and variable bus polling latency, which drastically increases jitter.
  • Shared Bus Contention: When the Ethernet interface shares internal buses with high-bandwidth peripherals (such as USB ports, Wi-Fi modules, or storage devices), data transfers compete for bandwidth, causing random transmission delays.
  • Direct Memory Access (DMA) Limits: Low-tier SBCs may lack dedicated multi-channel DMA controllers for network traffic, forcing the CPU to handle packet transfers between network buffers and memory manually.

2. Operating System Scheduling and Kernel Latency

Standard general-purpose operating systems (like standard Linux distributions) are optimized for overall throughput rather than deterministic latency:

  • Non-Real-Time Kernels: Default Linux kernels use completely fair schedulers (CFS) that can preempt networking tasks to run background system operations. Without a real-time patch (such as PREEMPT_RT), the time it takes the kernel to service a network event can vary widely.
  • Dynamic Voltage and Frequency Scaling (DVFS): Power-saving governors dynamically scale the CPU frequency up and down based on load. The delay incurred when the processor transitions between low-power and high-performance states introduces measurable latency spikes.
  • Interrupt Handling (IRQs): If network interface interrupts are handled by overloaded CPU cores or delayed by high-priority system tasks, incoming and outgoing packets sit in queues, causing jitter.

3. Network Stack and Driver Configuration

The configuration of the network stack and the network interface card (NIC) driver directly influences packet processing consistency:

  • Interrupt Coalescing: Network drivers often delay generating an interrupt until a certain number of packets arrive or a timer expires, a technique used to save CPU cycles. While this improves throughput, it creates jitter for low-latency, sparse traffic.
  • Queue Management and Bufferbloat: Large network buffers (TX/RX ring buffers and socket buffers) can lead to bufferbloat. If packets queue up behind larger data bursts, latency fluctuates based on queue depth.
  • Socket Options and Offloading: Lacking hardware checksum offloading or ignoring real-time socket priority flags (such as SO_PRIORITY or packet timestamping) forces the CPU to spend varying amounts of time processing packet headers.

4. Physical Layer and External Network Conditions

External factors outside the SBC hardware also contribute to jitter at the Ethernet interface:

  • Network Congestion and Switch Queuing: Intermediate network switches process packets using store-and-forward mechanisms. When multiple devices send traffic across the same switch or VLAN, queue contention introduces variable transit times.
  • Ethernet PHY and Cable Quality: Poor-quality cabling, electromagnetic interference (EMI), or improper grounding can cause frame checksum errors. The physical layer (PHY) or transport protocol (TCP) must then handle retransmissions, leading to severe latency variations.
  • Link Speed and Duplex Mismatches: Operating in half-duplex or suffering from auto-negotiation mismatches causes packet collisions and backoff delays, introducing extreme jitter compared to a stable, full-duplex Gigabit or Fast Ethernet connection.
