Setup LUKS Encrypted Storage on an ARM SBC

Securing data on an ARM single board computer (SBC) is critical if the device is deployed in accessible or remote environments. This guide details the process of using Linux Unified Key Setup (LUKS) and the cryptsetup utility to create, format, open, and manage an encrypted storage volume on an external USB drive, NVMe SSD, or secondary partition on an ARM-based system running Linux.

1. Install Cryptsetup

First, update your package repositories and install the cryptsetup package, which provides the tools needed to manage LUKS volumes.

sudo apt update
sudo apt install cryptsetup

2. Identify the Target Drive

Attach your storage drive to the ARM SBC. List all available block devices to identify the exact identifier for your drive or partition.

lsblk

Locate your target device (for example, /dev/sdb1 or /dev/nvme0n1p1). Ensure you select the correct partition, as the following steps will overwrite all existing data on it.

3. Initialize the LUKS Partition

Format the target partition with LUKS. You will be prompted to confirm the operation in uppercase (YES) and enter a strong passphrase.

sudo cryptsetup luksFormat /dev/sdb1

Note: On ARM devices with hardware cryptographic acceleration (such as ARMv8 Crypto Extensions), LUKS automatically utilizes AES hardware acceleration to maintain high read/write performance.

4. Open the Encrypted Container

To interact with the encrypted volume, map it to a virtual device under /dev/mapper/ using your chosen mapping name (e.g., secure_storage).

sudo cryptsetup open /dev/sdb1 secure_storage

Enter your passphrase when prompted. Once opened, the decrypted container will be accessible at /dev/mapper/secure_storage.

5. Create a Filesystem

Create a standard Linux filesystem, such as ext4, inside the decrypted container:

sudo mkfs.ext4 /dev/mapper/secure_storage

6. Mount the Encrypted Volume

Create a directory to act as the mount point and mount the decrypted volume to make it available for reading and writing.

sudo mkdir -p /mnt/secure_data
sudo mount /dev/mapper/secure_storage /mnt/secure_data

You can verify the volume is mounted properly by running df -h /mnt/secure_data.

7. Unmount and Lock the Volume

When you are done accessing your files, safely unmount the directory and close the LUKS mapping to lock your data:

sudo umount /mnt/secure_data
sudo cryptsetup close secure_storage

Once closed, the data remains encrypted and inaccessible until the container is reopened with the correct passphrase.
