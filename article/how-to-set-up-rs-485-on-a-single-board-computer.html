How to Set Up RS-485 on a Single Board Computer

Establishing an RS-485 serial communication link on a single board computer (SBC) requires interfacing a UART-to-RS-485 transceiver, wiring the differential data bus, enabling hardware serial interfaces within the operating system, and managing transmit/receive direction control. This guide outlines the essential hardware connections, system configurations, and software testing steps necessary to deploy a robust RS-485 network on modern SBC platforms like the Raspberry Pi, BeagleBone, or generic Linux development boards.

Step 1: Select the Proper Transceiver Hardware

Single board computers operate using standard TTL/CMOS logic levels (typically 3.3V or 5V), whereas RS-485 relies on differential voltage signaling across a balanced pair.

  • Use an external TTL-to-RS-485 transceiver IC (such as the MAX485, MAX3485 for 3.3V, or an SP3485) or a dedicated RS-485 HAT/expansion shield.
  • Ensure the transceiver's logic level matches your SBC’s GPIO voltage (use 3.3V transceivers for 3.3V GPIOs to prevent board damage).
  • Decide between an automatic direction control transceiver (which handles transmit/receive switching internally) or a manual control transceiver that uses Driver Enable (DE) and Receiver Enable (/RE) pins.

Step 2: Wire the RS-485 Bus

RS-485 uses a balanced pair designated as A (D-) and B (D+), along with a common ground reference.

  1. Connect Transceiver to SBC:
    • VCC/GND: Connect to the SBC's 3.3V/5V and Ground pins.
    • TXD (DI): Connect to the SBC’s UART TX pin.
    • RXD (RO): Connect to the SBC’s UART RX pin.
    • DE and /RE: Tie together and connect to a designated GPIO pin for flow control (if not using an auto-switching module).
  2. Connect the Field Bus:
    • Connect line A to the A line of other devices on the network.
    • Connect line B to the B line of other devices on the network.
    • Connect a shared signal ground wire across all nodes to avoid common-mode voltage issues.
  3. Termination and Bias:
    • Place a 120-ohm termination resistor across lines A and B at both physical ends of the communication bus.
    • Add pull-up and pull-down fail-safe biasing resistors if they are not integrated into the transceiver module.

Step 3: Enable the UART Interface on the SBC

By default, the primary UART on many SBCs is assigned to the serial console.

  1. Free the UART Port: Disable the serial console service so it does not interfere with raw data transmission.
  2. Enable Hardware UART: Enable the required UART overlay in the system configuration (e.g., modifying config.txt on Raspberry Pi OS or using Device Tree overlays on Armbian).
  3. Identify the Device Node: Confirm the assigned device path in Linux (typically /dev/ttyS0, /dev/ttyAMA0, or /dev/ttyUSB0 if using a USB-to-RS-485 adapter).

Step 4: Configure Direction Control (DE/RE)

Because RS-485 is commonly operated in half-duplex mode, the SBC must toggle the transceiver into transmit mode before sending data and return it to receive mode immediately afterward.

  • Kernel-Level RS-485 (Hardware RTS): Configure the Linux serial driver to handle RS-485 direction toggling automatically via the TIOCSRS485 ioctl command.
  • Manual GPIO Toggling: If using user-space control, set the DE/RE GPIO high before transmitting, wait for the UART transmission buffer to clear completely, and immediately set the pin low.
  • Auto-Direction Hardware: If using an auto-switching module, skip this step as the hardware handles direction changes automatically.

Step 5: Test and Verify the Link

Once the hardware and interfaces are configured, verify the data pipeline.

  1. Set Serial Parameters: Configure the baud rate, parity, data bits, and stop bits (e.g., 9600 8-N-1) using command-line utilities like stty: 
    stty -F /dev/ttyAMA0 9600 cs8 -cstopb -parenb
  2. Send Test Data: Use a terminal utility or a Python script (using libraries such as pyserial or minimalmodbus) to write bytes to the port: 
    echo "RS485 Test" > /dev/ttyAMA0
  3. Read Incoming Data: Read data on the remote node or capture it using a serial monitor utility to confirm bidirectional data transmission.
