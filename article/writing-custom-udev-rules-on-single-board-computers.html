Writing Custom Udev Rules on Single Board Computers

Single Board Computers (SBCs) frequently interact with external hardware, but Linux dynamically assigns device nodes like /dev/ttyUSB0 or /dev/video0 based on boot order, leading to broken dependencies. Writing custom udev rules solves this problem by binding hardware devices to predictable, persistent symbolic links or names based on unique hardware attributes such as serial numbers, vendor IDs, or physical port topologies.

1. Identify the Target Device Attributes

Connect the hardware device to the SBC and locate its current temporary kernel name (e.g., /dev/ttyUSB0). Query the device's properties using udevadm info to extract unique hardware identifiers:

udevadm info -a -n /dev/ttyUSB0

Scan the output for parent devices and note key identifying attributes, such as:

  • ATTRS{idVendor}: The USB vendor ID (e.g., "0403").
  • ATTRS{idProduct}: The USB product ID (e.g., "6001").
  • ATTRS{serial}: The unique hardware serial number.
  • KERNELS: The physical bus path (useful if devices share the same vendor/product ID and lack unique serial numbers).

2. Create the Udev Rule File

Udev rule files are stored in /etc/udev/rules.d/ and are processed in lexical order. Create a new file with a high numerical prefix to ensure it runs after default system rules:

sudo nano /etc/udev/rules.d/99-usb-serial.rules

3. Define the Rule Syntax

Construct the rule using match keys (==) to identify the hardware and assignment keys (=, +=) to apply settings.

Matching by Serial Number (Recommended): If the device has a unique serial number, create a deterministic symlink:

SUBSYSTEM=="tty", ATTRS{idVendor}=="0403", ATTRS{idProduct}=="6001", ATTRS{serial}=="A104XYZ", SYMLINK+="sensors/temp_sensor", MODE="0666"

Matching by Physical USB Port Path: If multiple identical devices lack unique serial numbers, bind them based on the physical USB port topology:

SUBSYSTEM=="tty", KERNELS=="1-1.2:1.0", SYMLINK+="actuator_motor", MODE="0666"

Common parameters include:

  • SUBSYSTEM: The kernel subsystem handling the device (e.g., tty, net, video4linux).
  • SYMLINK+=: Appends a persistent alias path under /dev/.
  • MODE: Sets the file permissions for non-root process access.
  • GROUP: Assigns group ownership (e.g., GROUP="dialout").

4. Reload and Trigger Udev Rules

Apply the updated configuration without rebooting the SBC by reloading the rules and triggering the udev subsystem:

sudo udevadm control --reload-rules
sudo udevadm trigger

5. Verify the Persistent Device Path

Check if the new symlink has been created and points correctly to the target device:

ls -l /dev/sensors/temp_sensor

Applications running on the SBC can now point directly to /dev/sensors/temp_sensor rather than the variable kernel node, ensuring deterministic hardware communication across reboots and reconnections.
