SBC Memory Controller Setup in Second-Stage Boot

During the boot sequence of a Single Board Computer (SBC), the initial Boot ROM lacks the resources to run complex operating systems directly from internal SRAM. The second-stage bootloader (such as U-Boot SPL or ARM Trusted Firmware BL2) is tasked with bringing up external volatile memory (DRAM). This article details the essential steps required to configure power domains, establish clock trees, calibrate PHY interfaces, program timing parameters, and verify the memory subsystem to ensure stable operation before loading the primary operating system.

1. Power and Clock Initialization

Before interacting with the memory controller, stable power and clock rails must be established:

  • Power Management IC (PMIC) Setup: Configure the PMIC via I2C or SPI to provide the required voltages for the DRAM core (VDD/VDDQ), memory controller, and termination circuits (VTT).
  • Phase-Locked Loop (PLL) Configuration: Lock the memory PLL to achieve the target operational frequency (e.g., DDR4-2400 or LPDDR4-3200).
  • Clock Routing and De-assertion of Reset: Enable clock gates for the DDR controller (DDRC) and physical layer (DDR PHY), then release their respective reset lines.

2. Pin Multiplexing and I/O Configuration

The physical interface between the System-on-Chip (SoC) and the DRAM chips must be conditioned for high-speed signal integrity:

  • Pad Multiplexing (Pinmux): Route DDR address, command, control, and data (DQ/DQS) lines to the physical I/O pads.
  • Electrical Property Tuning: Configure drive strengths, slew rates, and On-Die Termination (ODT) values according to PCB impedance profiles.

3. Controller and PHY Register Configuration

The DDR controller and PHY must be loaded with configuration parameters matching the specific memory topology:

  • Memory Geometry Definition: Set the number of ranks, banks, row/column address widths, and overall bus width (e.g., 16-bit, 32-bit).
  • JEDEC Timing Parameters: Program core timing constraints into the controller, including CAS Latency (\(t_{CL}\)), RAS-to-CAS Delay (\(t_{RCD}\)), Row Precharge Time (\(t_{RP}\)), and Refresh Cycle Time (\(t_{RFC}\)).
  • Burst and Refresh Settings: Configure burst length (typically BL8 or BL16) and auto-refresh intervals based on the ambient temperature and device specifications.

4. JEDEC Power-Up and Initialization Sequence

The memory controller executes the standardized JEDEC power-up protocol to bring the external DRAM chips out of a reset state:

  1. Maintain CKE (Clock Enable) low while applying power and clock signals.
  2. Assert and hold the DRAM RESET# pin for the duration specified by JEDEC standards (typically 200 microseconds).
  3. Drive CKE high and issue a NOP (No Operation) or DESELECT command.
  4. Execute the ZQ Calibration command to calibrate output drivers.
  5. Program DRAM Mode Registers (MR0 through MRx) to configure read/write latencies, ODT behavior, and low-power modes.

5. PHY Training and Calibration

High-frequency DDR interfaces require active training to compensate for board-level propagation delays and skew:

  • ZQL Calibration: Calibrate the PHY's internal impedance matching circuits against reference resistors.
  • Write Leveling: Adjust the timing of the write clock relative to the DQS strobe to compensate for fly-by routing skew.
  • Read DQS Gating / Alignment: Center the read strobe (DQS) within the read data (DQ) valid window.
  • Read/Write VREF Training: Sweep voltage reference levels to find the optimal eye margin for both reads and writes.

6. Validation and Memory Mapping

Once training completes successfully, the subsystem is validated before execution moves forward:

  • Built-In Self-Test (BIST): Run hardware-based pattern generation to verify bus integrity without CPU overhead.
  • Software Memory Test: Perform rapid write/read/verify operations on edge addresses (lowest and highest bounds) to detect addressing issues or cold solder joints.
  • Address Space Handoff: Enable address translation in the system interconnect (e.g., AXI/NoC) to map the DRAM to the global system address space, allowing the second-stage bootloader to load the next boot image (such as U-Boot proper, UEFI, or the Linux kernel) directly into RAM.
