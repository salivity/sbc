Secure Exposed Network Services on a Public SBC

Deploying a single-board computer (SBC) with a publicly routable IP address exposes it to persistent port scans, automated exploit attempts, and brute-force attacks. Securing these low-power devices requires a defense-in-depth approach that minimizes the attack surface while protecting resource-constrained hardware. This guide details the most effective methods to secure public-facing services on an SBC, covering access control, network hardening, service isolation, and automated threat mitigation.

1. Eliminate Direct Exposure with Overlay Networks and Tunnels

The most secure public port is one that is never opened. Instead of routing traffic directly to an exposed port on the SBC, use modern networking overlays:

  • Zero Trust Tunnels: Cloudflare Tunnels create an outbound-only connection from the SBC to Cloudflare's edge, exposing web services without opening inbound router ports or revealing your public IP.
  • Mesh VPNs: Implement WireGuard, Tailscale, or Nebula to restrict service access to authenticated private mesh network members, keeping all administrative and internal services hidden from the public internet.

2. Harden SSH and Remote Management

If direct remote access is required, the default administrative configuration must be strictly hardened:

  • Disable Password Authentication: Configure /etc/ssh/sshd_config with PasswordAuthentication no and enforce modern public-key authentication using Ed25519 keys.
  • Disable Root Login: Set PermitRootLogin no to prevent direct compromise of the root account.
  • Remove Default Usernames: Delete default vendor accounts (such as pi) and create a dedicated administrative user with sudo privileges.
  • Change the Default Port: Shifting SSH from port 22 to a non-standard high port eliminates the vast majority of automated bot noise.

3. Enforce a Default-Deny Firewall

Configure a host-based firewall using nftables or ufw to strictly control traffic flow:

  • Default-Drop Policy: Block all inbound and forwarded traffic by default; explicitly whitelist only required ports (e.g., ports 80 and 443 for web traffic).
  • Rate Limiting: Apply rate limits to public-facing connection endpoints at the firewall level to mitigate simple denial-of-service (DoS) attempts.

4. Deploy Automated Intrusion Prevention

Publicly routable devices encounter thousands of unauthorized access attempts daily. Automated intrusion prevention systems identify and block aggressive actors:

  • Fail2ban: Monitors log files for repeated authentication failures and dynamically adds temporary drop rules to the firewall.
  • CrowdSec: A modern, collaborative alternative to Fail2ban that shares threat intelligence across a distributed network to preemptively block known malicious IP addresses.

5. Terminate Traffic with a Hardened Reverse Proxy

Never expose backend application runtimes (such as Node.js, Python, or Go built-in servers) directly to the public internet:

  • TLS Termination: Place a production-grade reverse proxy (such as Caddy, Nginx, or Traefik) in front of applications to handle TLS encryption, automatic certificate renewal (via Let's Encrypt), and secure cipher negotiation.
  • Security Headers: Enforce strict HTTP response headers, including HTTP Strict Transport Security (HSTS), Content Security Policy (CSP), X-Frame-Options, and X-Content-Type-Options.

6. Containerize and Isolate Services

Container runtimes (such as Docker or Podman) prevent a compromised application from gaining host-level control:

  • Rootless Containers: Run containers under unprivileged user namespaces to prevent container breakout exploits from obtaining host root permissions.
  • Read-Only Filesystems: Mount container root filesystems as read-only and restrict write operations to dedicated temporary storage volumes.
  • Resource Limits: Define memory and CPU limits on containers to prevent a compromised or misbehaving service from exhausting the SBC's hardware resources.

7. Automate Patch Management

Unpatched vulnerabilities in publicly exposed software represent the highest risk factor:

  • Unattended Upgrades: Enable automatic security updates (such as the unattended-upgrades package on Debian/Ubuntu-based distributions) to patch the kernel and critical system libraries immediately upon release.
  • Minimal Installation: Remove unused packages, compilers, and background daemons to reduce the overall attack surface and preserve system memory.
