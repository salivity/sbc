Cross-Compile Custom Linux for ARM Single Board Computers

Cross-compiling a custom Linux distribution involves building the operating system components on a fast host architecture (typically x86_64) to run on a target ARM-based single board computer (SBC). This guide outlines the essential phases of the process, covering toolchain setup, bootloader compilation, kernel configuration, root filesystem creation, and storage media preparation.

1. Setting Up the Host Environment and Cross-Toolchain

Cross-compilation requires a dedicated toolchain capable of generating ARM machine code on your host machine.

  • Select the Target Architecture: Determine whether your board uses a 32-bit (e.g., armhf, arm-linux-gnueabihf) or 64-bit (e.g., aarch64, aarch64-linux-gnu) instruction set.
  • Install Prerequisites: Install essential build utilities such as build-essential, bison, flex, libssl-dev, bc, and the appropriate GNU cross-compiler toolchain via your host distribution's package manager.
  • Export Environment Variables: Simplify the build process by exporting architecture and compiler prefixes in your shell: 
    export ARCH=arm64
export CROSS_COMPILE=aarch64-linux-gnu-

2. Compiling the Bootloader (U-Boot)

The bootloader initializes hardware components (DRAM, clocks, storage) and loads the Linux kernel into memory.

  • Source Acquisition: Clone the official Das U-Boot repository or your board vendor's downstream fork.
  • Configuration: Load your target board’s default configuration file: 
    make <your_board>_defconfig
  • Compilation: Run make -j$(nproc) to generate board-specific boot binaries, such as u-boot.bin, u-boot-sunxi-with-spl.bin, or separate Secondary Program Loader (SPL) files.

3. Building the Linux Kernel and Device Trees

The Linux kernel interacts directly with the board's hardware, while Device Tree Blobs (DTBs) describe the non-discoverable hardware layout to the kernel.

  • Fetch Kernel Sources: Download stable mainline Linux kernel sources from kernel.org or the board vendor’s repository.
  • Configure the Kernel: Apply a baseline configuration for your target SoC: 
    make defconfig
    Use make menuconfig to enable board-specific drivers, file systems, and network protocols.
  • Build Binaries: Compile the kernel image, modules, and device trees: 
    make -j$(nproc) Image dtbs modules
  • Export Kernel Modules: Direct module outputs to a temporary directory for later inclusion in the root filesystem: 
    make modules_install INSTALL_MOD_PATH=./output/rootfs

4. Constructing the Root Filesystem (RootFS)

The RootFS contains all user-space libraries, system binaries, initialization systems, and configuration files.

  • Minimalist Approach (BusyBox): Compile BusyBox with the cross-compiler to generate core UNIX utilities in a minimal footprint.
  • Automated Build Systems (Buildroot / Yocto): For production environments, utilize Buildroot or the Yocto Project to automate the cross-compilation of the entire userspace, package dependencies, and custom init scripts.
  • Binary Distribution Base (Debootstrap): Create a Debian or Ubuntu ARM root filesystem using debootstrap combined with QEMU user-mode emulation (qemu-arm-static or qemu-aarch64-static) to run native package configuration.

5. Partitioning and Flashing the Storage Media

The final step is preparing the boot media (microSD card or eMMC) with the compiled components.

  • Partition the Disk: Use fdisk or parted to create a standard two-partition layout:
    • Partition 1 (Boot): Formatted as FAT32, flagged as bootable, containing the kernel image (Image or zImage), compiled device tree (.dtb), and boot configuration script (boot.scr or extlinux.conf).
    • Partition 2 (Root): Formatted as ext4, containing the root filesystem.
  • Install Bootloader: Write the bootloader binaries directly to the raw blocks or the boot partition according to the SoC's boot ROM specification: 
    sudo dd if=u-boot-sunxi-with-spl.bin of=/dev/sdX bs=1k seek=8 status=progress
  • Copy Kernel and RootFS: Mount the partitions, copy the boot assets into Partition 1, extract the root filesystem into Partition 2, and verify that /etc/fstab matches your partition UUIDs.

6. Booting and Verification

Insert the storage media into the ARM SBC, connect a USB-to-UART serial adapter to the board's serial debug pins, and open a terminal emulator (such as minicom or picocom) at the required baud rate (commonly 115200). Power the board to observe early bootloader output, kernel initialization, and the final user-space login prompt.
