Configure Custom PCIe Kernel Modules on SBCs

Configuring a custom Linux kernel module for proprietary PCIe hardware on a single board computer (SBC) requires setting up matching kernel headers, mapping PCIe Base Address Registers (BARs), implementing interrupt handling, and managing Direct Memory Access (DMA). This guide details the complete development and configuration workflow, from establishing the build environment to loading and verifying the driver on the target SBC.

1. Preparing the SBC Build Environment

The development environment requires kernel headers matching the exact kernel version running on the SBC.

  • Native Compilation: On SBCs with sufficient CPU and RAM, install the build tools and kernel headers directly: 
    sudo apt-get install build-essential linux-headers-$(uname -r)
  • Cross-Compilation: If building on a host machine, install the target architecture toolchain (e.g., aarch64-linux-gnu-gcc) and download the vendor-specific kernel source tree configured for the target board.

2. Validating Hardware Detection

Before writing driver code, verify that the SBC's PCIe controller enumerates the proprietary device. Connect the card to the SBC's PCIe or M.2/mini-PCIe slot and run:

lspci -nn -v

Identify the Vendor ID and Device ID (e.g., 1234:abcd). If the device does not appear, ensure the SBC's Device Tree (DT) enables the PCIe controller node and provides required power rails or clock signals.

3. Writing the PCIe Driver Core

The driver must register with the Linux PCIe subsystem using the pci_driver structure.

#include <linux/init.h>
#include <linux/module.h>
#include <linux/pci.h>

#define VENDOR_ID 0x1234
#define DEVICE_ID 0xabcd

static struct pci_device_id custom_pci_ids[] = {
    { PCI_DEVICE(VENDOR_ID, DEVICE_ID) },
    { 0, }
};
MODULE_DEVICE_TABLE(pci, custom_pci_ids);

static int custom_pci_probe(struct pci_dev *pdev, const struct pci_device_id *id) {
    int bar = 0;
    void __iomem *hw_addr;

    /* Enable PCIe device */
    if (pci_enable_device(pdev))
        return -EIO;

    /* Reserve PCIe I/O and memory resources */
    if (pci_request_regions(pdev, "custom_pci_driver"))
        goto disable_device;

    /* Map the hardware Base Address Register (BAR) */
    hw_addr = pci_iomap(pdev, bar, pci_resource_len(pdev, bar));
    if (!hw_addr)
        goto release_regions;

    /* Enable bus mastering for DMA capabilities */
    pci_set_master(pdev);

    pci_set_drvdata(pdev, hw_addr);
    return 0;

release_regions:
    pci_release_regions(pdev);
disable_device:
    pci_disable_device(pdev);
    return -EBUSY;
}

static void custom_pci_remove(struct pci_dev *pdev) {
    void __iomem *hw_addr = pci_get_drvdata(pdev);

    pci_iounmap(pdev, hw_addr);
    pci_release_regions(pdev);
    pci_disable_device(pdev);
}

static struct pci_driver custom_driver = {
    .name = "custom_pcie_driver",
    .id_table = custom_pci_ids,
    .probe = custom_pci_probe,
    .remove = custom_pci_remove,
};

module_pci_driver(custom_driver);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Hardware Engineer");
MODULE_DESCRIPTION("Custom Driver for Proprietary PCIe Peripheral");

4. Implementing Interrupts and DMA

For high-throughput proprietary hardware, configure interrupts and DMA buffers inside the probe function:

  • MSI/MSI-X Interrupts: Allocate MSI vectors using pci_alloc_irq_vectors(pdev, 1, 1, PCI_IRQ_MSI | PCI_IRQ_LEGACY). Bind the interrupt service routine using request_threaded_irq(pdev->irq, handler, thread_fn, IRQF_SHARED, "custom_pci_irq", dev).
  • Coherent DMA Mapping: Configure the DMA mask (dma_set_mask_and_coherent(&pdev->dev, DMA_BIT_MASK(32))) and allocate buffers via dma_alloc_coherent(&pdev->dev, size, &dma_handle, GFP_KERNEL).

5. Compiling and Loading the Module

Create a standard Makefile alongside the driver source file:

obj-m += custom_pcie.o

KDIR ?= /lib/modules/$(shell uname -r)/build
PWD := $(shell pwd)

default:
    $(MAKE) -C $(KDIR) M=$(PWD) modules

clean:
    $(MAKE) -C $(KDIR) M=$(PWD) clean

Execute the compilation, load the module into the running kernel, and verify:

make
sudo insmod custom_pcie.ko
dmesg | tail -n 20

To load the module automatically at boot, copy custom_pcie.ko to /lib/modules/$(uname -r)/extra/, run sudo depmod -a, and append the module name to /etc/modules.
