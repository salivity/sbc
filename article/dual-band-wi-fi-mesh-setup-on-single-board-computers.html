Dual-Band Wi-Fi Mesh Setup on Single Board Computers

Configuring dual-band Wi-Fi mesh networking on an array of single board computers (SBCs) enables resilient, high-throughput decentralized communication for edge computing, IoT clusters, and field deployments. By utilizing both 2.4 GHz and 5 GHz frequencies simultaneously, developers can dedicate high-frequency channels for high-bandwidth node-to-node backhaul while retaining the lower frequency for long-range connectivity or client access. This guide explains how to establish a dual-band mesh architecture using Linux kernel tools, standard IEEE 802.11s mesh interfaces, and B.A.T.M.A.N. Advanced (Better Approach To Mobile Adhoc Networking) routing.

1. Hardware and Driver Prerequisites

To implement a true dual-band mesh, each SBC must be equipped with wireless interfaces capable of simultaneous dual-band operation. This is typically achieved using either a dual-band, dual-concurrent (DBDC) integrated Wi-Fi module or two separate Wi-Fi adapters (e.g., an onboard 2.4 GHz radio and a secondary 5 GHz USB dongle).

Verify that the Wi-Fi drivers support mesh point mode (mesh point or 802.11s) by inspecting the iw capabilities:

iw list | grep "Supported interface modes" -A 8

Ensure mesh point is listed under the supported modes for both interfaces.

2. Dual-Interface Mesh Topology Strategy

A standard single-band mesh relies on one frequency, creating channel contention. A dual-band approach resolves this by establishing two distinct Layer 2 mesh domains:

  • 5 GHz Mesh (mesh5): Configured on a clean, wide channel (e.g., 80 MHz on Channel 36 or 149) for high-speed, low-latency inter-node communication.
  • 2.4 GHz Mesh (mesh24): Configured on standard non-overlapping channels (1, 6, or 11) for maximum range and penetration through obstacles.

Both mesh links are aggregated at Layer 2 using BATMAN-adv, which continuously assesses link quality and dynamically routes packets over the optimal band.

3. Step-by-Step Configuration

Step A: Install Required Packages

Install the wireless configuration tools and routing daemons on each SBC:

sudo apt update
sudo apt install iw batctl wireless-tools bridge-utils

Load the BATMAN-adv kernel module:

sudo modprobe batman-adv

Step B: Initialize IEEE 802.11s Mesh Interfaces

Create dedicated mesh interfaces for both the 2.4 GHz (wlan0) and 5 GHz (wlan1) physical radios. Replace the Mesh IDs (MeshID_24 and MeshID_5) and channel frequencies accordingly.

# Configure 2.4 GHz Mesh (Channel 1 -> 2412 MHz)
sudo ip link set wlan0 down
sudo iw dev wlan0 interface add mesh24 type mp mesh_id MeshCluster24
sudo ip link set mesh24 up
sudo iw dev mesh24 set channel 1

# Configure 5 GHz Mesh (Channel 36 -> 5180 MHz)
sudo ip link set wlan1 down
sudo iw dev wlan1 interface add mesh5 type mp mesh_id MeshCluster5
sudo ip link set mesh5 up
sudo iw dev mesh5 set channel 36

Step C: Aggregate Interfaces with BATMAN-adv

Attach both mesh interfaces to the BATMAN-adv virtual interface (bat0). BATMAN-adv handles routing metrics and dynamically selects the best interface for packet transport.

# Add mesh interfaces to BATMAN-adv
sudo batctl if add mesh24
sudo batctl if add mesh5

# Bring up the bat0 interface
sudo ip link set up dev mesh24
sudo ip link set up dev mesh5
sudo ip link set up dev bat0

Step D: Assign IP Addressing

Assign a static IP address to the bat0 virtual interface on each node within the same subnet:

# Example for Node 1
sudo ip addr add 192.168.199.1/24 dev bat0

# Example for Node 2
sudo ip addr add 192.168.199.2/24 dev bat0

4. Verification and Routing Diagnostics

Verify that the nodes discover each other across both frequency bands:

  • Check direct 802.11s peers: 
    iw dev mesh24 station dump
iw dev mesh5 station dump
  • Check BATMAN-adv mesh neighbors and link quality: 
    sudo batctl n
sudo batctl o

The output of batctl o displays the Transmit Quality (TQ) metric for each neighbor via both mesh24 and mesh5, demonstrating automatic traffic steering over the highest-performing link.

5. Automating on Boot

To persist the configuration across reboots, add the initialization commands to a systemd service file located at /etc/systemd/system/mesh-init.service:

[Unit]
Description=Dual-Band Wi-Fi Mesh Service
After=network.target

[Service]
Type=oneshot
ExecStart=/usr/local/bin/start-mesh.sh
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target

Place the initialization shell script in /usr/local/bin/start-mesh.sh, make it executable with chmod +x /usr/local/bin/start-mesh.sh, and enable the service via sudo systemctl enable mesh-init.service.
