Apply Device Tree Overlays at Runtime on Linux SBCs

Configuring Device Tree Overlays (DTOs) dynamically allows developers to reconfigure hardware pins, enable peripherals, and attach drivers on a Linux-powered single board computer without rebooting the system. This guide covers the end-to-end process of authoring a custom overlay source file, compiling it with the Device Tree Compiler, and applying or removing the overlay dynamically at runtime using the Linux kernel's configfs interface and user-space utilities.

1. Write the Device Tree Overlay Source (.dts)

A Device Tree Overlay modifies the base device tree by referencing specific nodes via labels or paths. Create a source file named custom_spi.dts to enable a peripheral such as an SPI controller:

/dts-v1/;
/plugin/;

/ {
    compatible = "allwinner,sun8i-h3", "arm,rk3399", "brcm,bcm2835";

    fragment@0 {
        target = <&spi0>;
        __overlay__ {
            status = "okay";
            #address-cells = <1>;
            #size-cells = <0>;

            spidev@0 {
                compatible = "spidev";
                reg = <0>;
                spi-max-frequency = <10000000>;
            };
        };
    };
};

Ensure /plugin/; is declared at the top, which tells the compiler to support dynamic resolution of target nodes.

2. Compile the Overlay to a Binary (.dtbo)

Compile the .dts file into a Device Tree Blob Overlay (.dtbo) using the Device Tree Compiler (dtc). The -@ flag is mandatory to generate symbol fixups:

dtc -@ -I dts -O dtb -o custom_spi.dtbo custom_spi.dts

3. Ensure Kernel Support for Runtime Overlays

Runtime insertion requires specific Linux kernel configurations enabled:

  • CONFIG_OF_CONFIGFS=y (Dynamic Device Tree overlay support via configfs)
  • CONFIG_OF_OVERLAY=y (Device Tree overlays)

Verify that the configfs filesystem is mounted. If it is not mounted automatically, mount it manually:

sudo mount -t configfs none /sys/kernel/config

4. Load the Overlay Using ConfigFS

Once configfs is active, the kernel exposes the /sys/kernel/config/device-tree/overlays/ directory.

  1. Create a new directory for your overlay:
sudo mkdir /sys/kernel/config/device-tree/overlays/custom_spi
  1. Push the compiled .dtbo into the dtbo property:
sudo cp custom_spi.dtbo /sys/kernel/config/device-tree/overlays/custom_spi/dtbo
  1. Confirm that the kernel parsed the overlay:
cat /sys/kernel/config/device-tree/overlays/custom_spi/status

A return value of applied indicates the hardware node is active. You can also run dmesg | tail to view kernel driver initialization messages.

5. Remove the Overlay at Runtime

To detach the overlay, release the hardware resources, and unload the associated drivers, simply remove the directory created in configfs:

sudo rmdir /sys/kernel/config/device-tree/overlays/custom_spi

6. Alternative: Platform-Specific User-Space Helpers

Some Linux distributions include specialized utilities to manage runtime overlays:

  • Raspberry Pi OS: Use dtoverlay custom_spi.dtbo to load, and dtoverlay -r custom_spi to unload.
  • BeagleBone / Debian (Cape Manager): Dynamic loading can often be handled via helper scripts or custom udev rules interfacing with /sys/devices/platform/bone_capemgr.
