Hardware vs Software FPU on Single Board Computers

Single board computers (SBCs) rely on floating-point arithmetic to process non-integer math, which is critical for tasks like sensor data processing, computer vision, and 3D rendering. The primary difference between hardware-based and software-based floating-point units (FPUs) lies in the execution method: a hardware FPU utilizes dedicated physical circuits and registers built directly into the processor to compute decimals in real time, whereas a software FPU uses standard integer arithmetic instructions to emulate floating-point operations through software routines, resulting in significantly lower computational performance.

Execution Mechanism

A hardware FPU is an integrated mathematical coprocessor or execution pipeline within the SBC's system on a chip (SoC). When a program executes a floating-point instruction (such as standard IEEE 754 operations), the processor passes the instruction directly to the hardware FPU, which processes the calculation in one or a few clock cycles using dedicated registers (like ARM NEON or VFP registers).

A software FPU, often referred to as software floating-point emulation (soft-float), lacks dedicated mathematical execution logic. When the CPU encounters a floating-point calculation, it delegates the operation to runtime software libraries (such as libgcc). The library breaks the floating-point calculation down into dozens or hundreds of basic integer and bitwise instructions, executing them sequentially across standard general-purpose registers.

Performance and Latency

  • Hardware FPU: Executes mathematical operations with extremely low latency. Basic operations such as addition, subtraction, and multiplication typically take 1 to 4 clock cycles, enabling real-time data processing and high throughput.
  • Software FPU: Introduces substantial latency overhead. Emulating a single mathematical operation via integer instructions can require between 20 and 100+ clock cycles depending on the complexity of the operation (e.g., division or trigonometric functions), causing severe CPU bottlenecks during math-heavy workloads.

Power and Thermal Efficiency

While hardware FPUs add physical silicon to the SoC—momentarily increasing peak power draw during active calculations—they complete tasks substantially faster (known as the "race-to-sleep" principle). This allows the processor core to quickly return to an idle state, resulting in lower overall energy consumption.

Software FPUs keep the main CPU cores pegged at high utilization for extended periods to complete simple calculations. This prolonged processing time leads to higher total energy consumption and increased thermal output under continuous mathematical workloads.

Compiler Configuration and ABI Compatibility

The choice of floating-point implementation affects how software is compiled and run on an SBC:

  • Hard-Float ABI (e.g., armhf): Compilers generate direct FPU machine code and pass function arguments inside hardware floating-point registers. Binaries compiled for hard-float require hardware FPU support and will not run on soft-float systems.
  • Soft-Float ABI (e.g., armel): Compilers insert library calls for math operations and pass floating-point values using integer registers. While compatible with lower-end processors lacking an FPU, the resulting binaries run significantly slower.

SBC Applications and Selection

Hardware FPUs are standard on modern, performance-oriented SBCs (such as Raspberry Pi 2/3/4/5 and comparable ARM Cortex-A boards) intended for multimedia, machine learning inference, and complex robotics.

Software FPUs are typically restricted to ultra-low-cost or resource-constrained micro-SBCs and older embedded architectures (such as ARM7TDMI or Cortex-M0 devices) where minimizing silicon area, die cost, and base chip complexity outweighs the need for high-speed mathematical processing.
