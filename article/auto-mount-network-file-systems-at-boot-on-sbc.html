Auto Mount Network File Systems at Boot on SBC

Automatically mounting a Network File System (NFS) or Server Message Block (SMB/CIFS) share at boot on a Single Board Computer (SBC) ensures continuous access to remote storage for media servers, backups, or lightweight clustering. This guide covers the complete configuration process using the Linux /etc/fstab file, including dependency packages, network-wait parameters to prevent boot delays, credential management, and mount verification on distributions such as Raspberry Pi OS, Armbian, and Debian.

Step 1: Install Required Client Utilities

Before configuring automatic mounts, install the client tools corresponding to your network protocol.

For NFS shares:

sudo apt update
sudo apt install nfs-common -y

For SMB/CIFS (Windows/Samba) shares:

sudo apt update
sudo apt install cifs-utils -y

Step 2: Create a Local Mount Directory

Create the target directory on your SBC where the remote storage will be attached:

sudo mkdir -p /mnt/network_storage

Set permissions if necessary so your non-root user can read and write:

sudo chown -R $USER:$USER /mnt/network_storage

Step 3: Secure SMB Credentials (SMB/CIFS Only)

If using SMB/CIFS, avoid putting plain-text passwords in /etc/fstab. Create a secure credentials file:

sudo nano /etc/samba_credentials

Add your credentials inside the file:

username=your_share_username
password=your_share_password

Restrict permissions so only the root user can read it:

sudo chmod 600 /etc/samba_credentials

Step 4: Configure /etc/fstab

Open the filesystem table configuration file:

sudo nano /etc/fstab

Append one of the following configuration lines to the bottom of the file.

Option A: NFS Configuration

192.168.1.100:/path/to/nfs /mnt/network_storage nfs defaults,_netdev,nofail,x-systemd.automount 0 0

Option B: SMB/CIFS Configuration

//192.168.1.100/share_name /mnt/network_storage cifs credentials=/etc/samba_credentials,_netdev,nofail,x-systemd.automount,uid=1000,gid=1000 0 0

Key Options Explained:

  • _netdev: Informs the init system to wait until the network interface is online before attempting the mount.
  • nofail: Prevents the SBC from halting the boot process if the network share is offline or unreachable.
  • x-systemd.automount: Defers the actual connection until the directory is first accessed, ensuring reliable booting over Wi-Fi or slow-initializing Ethernet interfaces.
  • uid=1000,gid=1000: (CIFS only) Maps ownership of the mounted files to the default SBC user ID.

Step 5: Test and Verify the Mount

Never reboot immediately after editing /etc/fstab. Test the configuration to avoid boot errors.

  1. Reload systemd daemon definitions:

    sudo systemctl daemon-reload

  2. Mount all entries declared in /etc/fstab:

    sudo mount -a

  3. Verify that the share is mounted properly:

    df -h /mnt/network_storage

If the mount appears in the df -h output without errors, the remote file system will now attach automatically each time the SBC boots.
