How to Port FreeRTOS to ARM Cortex-M

Porting FreeRTOS to an ARM Cortex-M single board computer (SBC) involves integrating the FreeRTOS kernel into the target hardware's board support package (BSP), configuring the processor's core system interrupts, and tailoring the RTOS configuration file to match the board’s hardware specifications. This guide outlines the essential steps to prepare the source code, map the necessary exception vectors, configure the kernel, and verify the real-time operating system on target hardware.

1. Gather Required Files and Toolchain

Before beginning the port, prepare your development environment and collect the required source trees:

  • Toolchain/IDE: An ARM-supported toolchain such as GCC (via Arm GNU Toolchain), Keil MDK, or IAR Embedded Workbench.
  • Vendor BSP/CMSIS: The board-specific startup code, linker script, and CMSIS (Cortex Microcontroller Software Interface Standard) core header files provided by the silicon vendor.
  • FreeRTOS Kernel Source: Download the latest FreeRTOS release.

2. Organize FreeRTOS Source Directory

Extract the kernel source and include only the necessary components in your project:

  • Core Kernel: Add tasks.c, queue.c, list.c, timers.c (optional), and event_groups.c (optional) from the FreeRTOS/Source/ directory.
  • Port Layer: Cortex-M architecture-specific code is already provided by FreeRTOS. Navigate to FreeRTOS/Source/portable/[Compiler]/[Architecture]/ (e.g., portable/GCC/ARM_CM4F/ for a Cortex-M4 with FPU using GCC) and add port.c and portmacro.h.
  • Memory Management: Add one memory allocation scheme from FreeRTOS/Source/portable/MemMang/ (e.g., heap_4.c).

3. Configure FreeRTOSConfig.h

Create or adapt a FreeRTOSConfig.h file in your application's include path. This header tailors the kernel to your specific board:

  • CPU Clock Rate: Define configCPU_CLOCK_HZ with the actual system core clock frequency (e.g., SystemCoreClock).
  • Tick Rate: Define configTICK_RATE_HZ (typically set between 100 and 1000 Hz).
  • Heap Size: Set configTOTAL_HEAP_SIZE based on the available SRAM on your board.
  • Interrupt Priorities: Define configKERNEL_INTERRUPT_PRIORITY and configMAX_SYSCALL_INTERRUPT_PRIORITY according to the number of interrupt priority bits implemented in your Cortex-M variant (typically 3 to 4 bits).

4. Map Cortex-M Exception Handlers

FreeRTOS relies on three core Cortex-M exception handlers to manage context switching and time tracking:

  1. vPortSVCHandler (SVC): Used to start the first task.
  2. xPortPendSVHandler (PendSV): Used to perform context switches between tasks.
  3. xPortSysTickHandler (SysTick): Used to generate the RTOS tick interrupt.

Map these handlers in your project using one of two methods:

  • Preprocessor Mapping (Recommended): Add the following defines to FreeRTOSConfig.h: 
    #define vPortSVCHandler     SVC_Handler
#define xPortPendSVHandler  PendSV_Handler
#define xPortSysTickHandler SysTick_Handler
  • Vector Table Editing: Alternatively, edit the interrupt vector table in the startup assembly file (startup_*.s) to directly reference vPortSVCHandler, xPortPendSVHandler, and xPortSysTickHandler.

5. Initialize Hardware and Start the Scheduler

Set up the application entry point in main.c:

  1. Initialize the board's system clocks, GPIOs, and debug peripherals.
  2. Create at least one initial task using xTaskCreate() or xTaskCreateStatic().
  3. Call vTaskStartScheduler() to start multitasking.
#include "FreeRTOS.h"
#include "task.h"

void vBlinkTask(void *pvParameters) {
    for (;;) {
        // Toggle an onboard LED
        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

int main(void) {
    // 1. Board hardware initialization
    Hardware_Init();

    // 2. Task creation
    xTaskCreate(vBlinkTask, "Blink", configMINIMAL_STACK_SIZE, NULL, 1, NULL);

    // 3. Start Scheduler
    vTaskStartScheduler();

    // Should never reach here if scheduler started successfully
    for (;;);
}

6. Build, Flash, and Validate

Compile the project, flash the binary to the board using a debugger (e.g., J-Link, ST-LINK, or OpenOCD), and verify the port:

  • Ensure the tick counter increments by checking the return value of xTaskGetTickCount().
  • Verify that task delays work correctly with vTaskDelay().
  • Enable stack overflow detection (configCHECK_FOR_STACK_OVERFLOW = 2) during debugging to catch memory issues.
