How to Configure ALSA Sound Cards via Device Tree Overlays

Configuring a custom ALSA (Advanced Linux Sound Architecture) sound card on an embedded single-board computer (SBC) requires interfacing your audio hardware with the Linux kernel through Device Tree Overlays (DTOs). This article covers the essential process: defining the digital audio interface (DAI) and codec bindings, constructing the .dts overlay source, compiling it into a .dtbo binary, applying the overlay via the bootloader or runtime configuration, and verifying the ALSA sound card using standard Linux audio utilities.

1. Identify Hardware Components and Linux Bindings

Before writing the overlay, identify the two primary components of your audio subsystem:

  • The CPU DAI: The System-on-Chip (SoC) audio interface, typically an I2S, TDM, or PDM controller.
  • The Codec DAI: The digital audio interface of the external DAC, ADC, or audio codec (e.g., PCM5102A, WM8960).

Most standard audio interfaces can be represented in Linux using the generic simple-audio-card or audio-graph-card drivers. The simple-audio-card binding is the most common approach for linking a single I2S controller to an external codec.

2. Write the Device Tree Overlay (.dts)

Create a Device Tree source file (e.g., custom-soundcard.dts) that specifies the sound card routing, clocks, and links between the CPU DAI and the codec DAI.

/dts-v1/;
/plugin/;

/ {
    compatible = "allwinner,sun8i-h3", "arm,sun8i", "brcm,bcm2835", "rockchip,rk3399";

    fragment@0 {
        target = <&i2s0>;
        __overlay__ {
            status = "okay";
            pinctrl-0 = <&i2s0_pins>;
            pinctrl-names = "default";
        };
    };

    fragment@1 {
        target-path = "/";
        __overlay__ {
            sound {
                compatible = "simple-audio-card";
                simple-audio-card,name = "Custom-I2S-Card";
                simple-audio-card,format = "i2s";
                simple-audio-card,bitclock-master = <&dailink0_master>;
                simple-audio-card,frame-master = <&dailink0_master>;

                simple-audio-card,widgets =
                    "Speaker", "External Speaker",
                    "Microphone", "External Mic";
                simple-audio-card,routing =
                    "External Speaker", "Line Out",
                    "Line In", "External Mic";

                dailink0_master: simple-audio-card,cpu {
                    sound-dai = <&i2s0>;
                    dai-tdm-slot-num = <2>;
                    dai-tdm-slot-width = <32>;
                };

                simple-audio-card,codec {
                    sound-dai = <&pcm5102a_codec>;
                };
            };

            pcm5102a_codec: pcm5102a-codec {
                #sound-dai-cells = <0>;
                compatible = "ti,pcm5102a";
                status = "okay";
            };
        };
    };
};

3. Compile the Device Tree Overlay

Use the Device Tree Compiler (dtc) with the @ flag enabled to allow unresolved symbol references that will be resolved against the base device tree at load time:

dtc -@ -I dts -O dtb -o custom-soundcard.dtbo custom-soundcard.dts

4. Deploy and Enable the Overlay

Move the compiled .dtbo binary to the appropriate system overlay directory, usually /boot/overlays/ or /boot/dtbs/overlays/.

Static Loading via Bootloader

Enable the overlay in your board’s bootloader configuration file:

  • Raspberry Pi OS (/boot/config.txt or /boot/firmware/config.txt): 
    dtoverlay=custom-soundcard
  • Armbian / U-Boot (/boot/armbianEnv.txt or extlinux.conf): 
    user_overlays=custom-soundcard

Dynamic Loading at Runtime

If supported by your kernel via ConfigFS, apply the overlay dynamically without rebooting:

mkdir -p /sys/kernel/config/device-tree/overlays/custom-soundcard
cat custom-soundcard.dtbo > /sys/kernel/config/device-tree/overlays/custom-soundcard/dtbo

5. Verify the Sound Card Configuration

After applying the overlay (and rebooting if configured statically), confirm that the ALSA subsystem has registered the audio card:

  1. Check ALSA playback devices:

    aplay -l

    You should see Custom-I2S-Card listed along with its card and device numbers.

  2. Inspect kernel boot messages for driver initialization:

    dmesg | grep -E "asoc|sound|i2s"

  3. Test playback to verify bit clocks and frame synchronizations:

    speaker-test -D hw:Custom-I2S-Card,0 -c 2 -r 48000 -t wav
