Configure Custom Baud Rates on Single Board Computers

Configuring custom, non-standard baud rates on a single board computer (SBC) is essential when interfacing with specialized sensors, legacy industrial hardware, or custom microcontrollers. While standard serial configurations typically rely on predefined rates like 9600 or 115200, modern Linux-based SBCs allow developers to set arbitrary baud rates using low-level kernel interfaces such as termios2, user-space serial libraries, or command-line utilities. This guide outlines the most effective methods to achieve exact baud rates on SBC platforms.

Understanding the Standard Termios Limitation

Standard POSIX serial interfaces utilize the termios API with functions like cfsetispeed() and cfsetospeed(). These functions only accept predefined macro constants (such as B115200 or B38400). If a peripheral requires an arbitrary rate—such as 250,000 baud for DMX or 31,250 baud for MIDI—the standard POSIX calls will fail or reject the value.

To overcome this, developers must interact with the Linux kernel's extended termios2 structure via direct ioctl system calls or use tools that implement this mechanism internally.

Method 1: Using the Linux termios2 API in C/C++

The standard and most reliable programmatic approach on Linux-based SBCs (such as Raspberry Pi, BeagleBone, or Rock Pi) is the termios2 interface.

  1. Include the kernel header instead of the standard userspace header:

    #include <asm/termios.h>
#include <sys/ioctl.h>
#include <fcntl.h>
#include <unistd.h>

  2. Open the serial port file descriptor:

    int fd = open("/dev/ttyUSB0", O_RDWR | O_NOCTTY | O_NDELAY);

  3. Read the current settings, apply the BOTHER flag, and specify the exact baud rate:

    struct termios2 tio;

// Get current settings using TCGETS2
ioctl(fd, TCGETS2, &tio);

// Clear standard baud rate masks and enable custom speed flag
tio.c_cflag &= ~CBAUD;
tio.c_cflag |= BOTHER;

// Set arbitrary input and output baud rate
tio.c_ispeed = 250000;
tio.c_ospeed = 250000;

// Apply new settings using TCSETS2
ioctl(fd, TCSETS2, &tio);

Method 2: Python (PySerial)

For rapid development or scripting on an SBC, the pySerial library natively handles non-standard baud rates on Linux. PySerial detects whether the platform supports termios2 or custom divisors and applies them automatically.

import serial

# Pass the custom baud rate as a direct integer
ser = serial.Serial(
    port='/dev/ttyAMA0',
    baudrate=250000,
    timeout=1
)

ser.write(b'Hello Device')
ser.close()

Method 3: Command-Line Utilities

GNU stty

Modern implementations of GNU Coreutils stty support arbitrary baud rate values directly:

stty -F /dev/ttyS0 250000

setserial Custom Divisors (Legacy Hardware)

For older UART drivers that do not support BOTHER, developers can configure a custom clock divisor using setserial:

  1. Set the port to use the custom divisor flag:

    setserial /dev/ttyS0 spd_cust

  2. Calculate the divisor based on the UART base clock: \[\text{Divisor} = \frac{\text{UART Base Clock}}{\text{Target Baud Rate}}\]

  3. Apply the custom divisor:

    setserial /dev/ttyS0 divisor <calculated_divisor>

Hardware and Clock Considerations

When configuring non-standard baud rates, developers must verify the hardware limitations of the SBC's UART controller:

  • Clock Divisor Rounding Errors: UART controllers generate baud rates by dividing a base clock. If the target baud rate cannot be divided evenly from the UART base clock, a timing error percentage is introduced. Most serial communication tolerates an error margin of up to \(\pm 2\% - 3\%\).
  • Device Tree and Firmware Clock Adjustments: On platforms like the Raspberry Pi, hardware UART clocks (PL011) can be locked or scaled by system power management. Setting init_uart_clock or modifying Device Tree overlays ensures the UART base clock remains stable and high enough to generate the desired baud rate accurately.
