ext4 vs Btrfs Performance on SD Card SBCs

Single-board computers (SBCs) like the Raspberry Pi frequently rely on micro-SD cards for storage, making filesystem choice critical for system speed and hardware longevity. This article compares ext4 and Btrfs across raw input/output performance, system resource consumption, flash wear, and feature trade-offs to help you decide which filesystem best suits an SD-card-reliant device.

Read and Write Throughput

  • ext4: Consistently delivers higher raw throughput and lower latency on SD cards. Its mature, lightweight design handles small-file random writes and sequential operations with minimal overhead, allowing low-end SD cards to reach their maximum potential speed.
  • Btrfs: Introduces measurable overhead due to its Copy-on-Write (CoW) architecture. When files are modified, Btrfs writes new data to an open block before updating metadata pointers, causing fragmentation on slow flash storage and resulting in lower random write speeds compared to ext4.

SD Card Wear and Write Amplification

Micro-SD cards use basic flash controllers with limited wear-leveling capabilities.

  • ext4 (Journaling): Modifies data in place and uses a lightweight journal to record metadata changes. This leads to fewer background write cycles, extending the operational lifespan of inexpensive SD cards.
  • Btrfs (Copy-on-Write): Generates higher write amplification through metadata updates and continuous allocation of new blocks. However, Btrfs allows users to enable transparent compression (such as zstd or lzo), which reduces the total physical bytes written to the flash media and can offset write amplification.

CPU and Memory Overhead

  • ext4: Operates with minimal CPU and memory footprints. It is ideally suited for single-core or low-RAM SBC configurations where background filesystem tasks could stall user-space applications.
  • Btrfs: Consumes significantly more RAM and CPU cycles to maintain B-trees, calculate data checksums, and manage CoW operations. On lower-spec SBCs (such as devices with 512 MB or 1 GB of RAM), Btrfs can cause system sluggishness during heavy disk I/O.

Features and Data Reliability

  • ext4: Provides basic journaling to recover from unexpected power loss. It lacks built-in snapshotting, dynamic subvolumes, and silent data corruption detection.
  • Btrfs: Includes native subvolumes, instant snapshots, data scrubbing, and block-level checksums. If an SD card suffers from silent bit-rot, Btrfs detects the corruption immediately, whereas ext4 may continue reading corrupted files without warning.

Key Recommendations

  • Choose ext4 if your priority is raw performance, maximum SD card lifespan, minimal CPU/RAM usage, and standard SBC tasks like media servers or retro gaming.
  • Choose Btrfs if you need instant system rollback snapshots via subvolumes, require transparent storage compression to save space, or need data integrity checksums for critical local files, and you have configured the mount options with compress=zstd, noatime, and space_cache=v2.
