Configure Static IP Routing on Multi-Homed SBC

This guide explains how developers can configure static IP routing on a multi-homed single board computer (SBC) running Linux. A multi-homed SBC connects to two or more network interfaces—such as dual Ethernet ports, an Ethernet port and Wi-Fi, or cellular modems—simultaneously. You will learn how to inspect network interfaces, define temporary and persistent static routes, handle default gateway conflicts, and implement policy-based routing to ensure traffic is correctly directed across distinct subnets.

1. Inspect Existing Interfaces and Routes

Before applying static routes, identify the active network interfaces and inspect the current routing table.

Display all active interfaces:

ip link show

Common interface names include eth0, eth1, wlan0, or end0.

View the current kernel routing table:

ip route show

2. Understand Default Gateway Conflicts

A multi-homed SBC should typically have only one default gateway (default via <IP> dev <interface>). If multiple interfaces obtain default gateways via DHCP, metric conflicts and asymmetric routing occur.

To avoid conflicts:

  • Assign the default gateway only to the interface that accesses the primary network or public internet.
  • Use explicit static routes for all secondary or isolated local subnets.

3. Add Temporary Static Routes Using iproute2

Temporary routes are applied immediately to test configurations before making them persistent.

Route a Specific Subnet Through a Secondary Interface

To route traffic destined for 192.168.20.0/24 through a gateway 10.0.0.1 on eth1:

sudo ip route add 192.168.20.0/24 via 10.0.0.1 dev eth1

Route Traffic to a Specific Host

To reach a single host 192.168.30.50 directly out of interface eth1:

sudo ip route add 192.168.30.50 dev eth1

Delete a Route

sudo ip route del 192.168.20.0/24 via 10.0.0.1 dev eth1

4. Make Static Routes Persistent

Different SBC distributions use different network management frameworks. Choose the method matching your operating system.

Option A: Netplan (Ubuntu, Debian 12+)

Edit the YAML configuration file in /etc/netplan/ (e.g., /etc/netplan/01-netcfg.yaml):

network:
  version: 2
  renderer: networkd
  ethernets:
    eth0:
      dhcp4: true
      # Primary interface with default gateway
    eth1:
      dhcp4: false
      addresses:
        - 10.0.0.2/24
      routes:
        - to: 192.168.20.0/24
          via: 10.0.0.1
          metric: 100

Apply the changes:

sudo netplan apply

Option B: systemd-networkd (Arch Linux ARM, OpenWrt, Yocto)

Create or edit the network unit file for the secondary interface (e.g., /etc/systemd/network/10-eth1.network):

[Match]
Name=eth1

[Network]
Address=10.0.0.2/24

[Route]
Destination=192.168.20.0/24
Gateway=10.0.0.1
Metric=100

Restart the network service:

sudo systemctl restart systemd-networkd

Option C: /etc/network/interfaces (Legacy Debian / Raspberry Pi OS)

Add up ip route add commands directly under the interface stanza:

auto eth1
iface eth1 inet static
    address 10.0.0.2
    netmask 255.255.255.0
    up ip route add 192.168.20.0/24 via 10.0.0.1 dev eth1
    down ip route del 192.168.20.0/24 via 10.0.0.1 dev eth1

Restart networking:

sudo systemctl restart networking

5. Configure Policy-Based Routing for Multi-Homing

When incoming traffic arrives on a secondary interface, standard routing might send the response out via the primary interface's default gateway, causing packets to be dropped by firewalls. Policy-based routing fixes this by replying via the interface that received the request.

  1. Define a custom routing table: Append a custom table entry to /etc/iproute2/rt_tables:

    echo "200 custom_eth1" | sudo tee -a /etc/iproute2/rt_tables

  2. Add a default route to the custom table:

    sudo ip route add default via 10.0.0.1 dev eth1 table custom_eth1
sudo ip route add 10.0.0.0/24 dev eth1 src 10.0.0.2 table custom_eth1

  3. Add routing rules based on source IP:

    sudo ip rule add from 10.0.0.2/32 table custom_eth1

6. Verify Static Routes

Test your routing configuration using the following commands:

  • Check which interface handles a destination IP: 
    ip route get 192.168.20.15
  • Ping through a specific interface: 
    ping -I eth1 192.168.20.15
  • Trace network hops: 
    traceroute -i eth1 192.168.20.15
