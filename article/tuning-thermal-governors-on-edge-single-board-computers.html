Tuning Thermal Governors on Edge Single Board Computers

Edge single board computers (SBCs) frequently encounter thermal throttling under sustained workloads, causing abrupt CPU frequency drops and degraded performance. Developers prevent these sudden drops by fine-tuning the Linux kernel's thermal framework, replacing default reactive policies with predictive control loops, adjusting thermal zones in the Device Tree, and optimizing Dynamic Voltage and Frequency Scaling (DVFS) tables. This guide outlines the exact strategies developers use to configure thermal governors, calibrate Proportional-Integral-Derivative (PID) constants, and maintain maximum sustainable compute throughput.

1. Selecting the Appropriate Thermal Governor

The Linux thermal framework provides several governor policies under /sys/class/thermal/. Default configurations often rely on reactive governors that cause erratic frequency oscillations. Selecting the right governor is the first step in stabilizing performance:

  • Step-Wise: Increases or decreases cooling states one step at a time based on thermal trends. While simple, it often reacts too late to rapid thermal spikes caused by bursty AI or video workloads.
  • Power Allocator (IPA - Intelligent Power Allocation): The preferred governor for edge SBCs. It uses a closed-loop Proportional-Integral-Derivative (PID) algorithm to dynamically allocate a power budget across CPU and GPU cores before temperatures reach critical throttling limits.
  • User Space: Offloads thermal management decisions to user-space daemons, useful when custom application-level scheduling is required.

To enable the Power Allocator governor dynamically via sysfs:

echo "power_allocator" > /sys/class/thermal/thermal_zone0/policy

2. Modifying Device Tree Thermal Zones and Trip Points

Governors make decisions based on trip points defined in the SBC’s Device Tree Source (.dts). Hard drops occur when the temperature hits a single, aggressively configured critical or passive trip point. Developers refine these in the thermal-zones node:

  • Staggered Passive Trip Points: Create multiple intermediate temperature thresholds (e.g., 65°C, 75°C, 85°C) instead of a single drop at 80°C. This allows the system to gradually step down frequency or engage cooling fans rather than crashing to the lowest frequency state.
  • Hysteresis Tuning: Define a hysteresis value (e.g., 2000 m°C to 5000 m°C) to prevent rapid toggling between cooling states when the temperature hovers around a trip point.

Example Device Tree snippet:

thermal-zones {
    cpu_thermal: cpu-thermal {
        polling-delay-passive = <250>; /* Polling interval in ms */
        polling-delay = <1000>;

        trips {
            cpu_alert: trip-point-0 {
                temperature = <65000>;
                hysteresis = <2000>;
                type = "passive";
            };
            cpu_throttle: trip-point-1 {
                temperature = <80000>;
                hysteresis = <5000>;
                type = "passive";
            };
        };
    };
};

3. Calibrating Power Allocator PID Parameters

When using the Intelligent Power Allocation (IPA) governor, developers tune the PID loop constants to eliminate temperature overshoot and steady-state oscillation:

  • \(k_p\) (Proportional Gain): Dictates how aggressively the system reduces power based on current temperature error. High \(k_p\) causes rapid throttling spikes; low \(k_p\) allows temperature overshoots.
  • \(k_i\) (Integral Gain): Accumulates past temperature errors to eliminate steady-state offsets under sustained continuous workloads.
  • \(k_d\) (Derivative Gain): Reacts to the rate of temperature change, applying pre-emptive cooling during steep temperature rises.
  • sustainable_power: Sets the estimated thermal dissipation capacity (in milliwatts) of the SBC's heatsink/enclosure.

These parameters can be tuned in real time under /sys/class/thermal/thermal_zoneX/:

echo 150 > /sys/class/thermal/thermal_zone0/k_pu # Proportional gain (undershoot)
echo 100 > /sys/class/thermal/thermal_zone0/k_po # Proportional gain (overshoot)
echo 10  > /sys/class/thermal/thermal_zone0/k_i  # Integral gain
echo 5   > /sys/class/thermal/thermal_zone0/k_d  # Derivative gain
echo 2500 > /sys/class/thermal/thermal_zone0/sustainable_power # mW

4. Aligning DVFS (cpufreq) Governors with Thermal Boundaries

Thermal drops often occur when the CPU governor (cpufreq) aggressively ramps to maximum frequency, generating a massive heat spike that forces immediate thermal throttling.

  • Use schedutil over performance: The schedutil governor utilizes kernel scheduler utilization data to scale frequencies smoothly, avoiding unnecessary peak-frequency bursts that trigger thermal trips.
  • Cap Maximum Frequencies (scaling_max_freq): Clamping the top 100–200 MHz off the CPU's maximum clock speed often reduces thermal dissipation by 20–30% with negligible impact on throughput, keeping the board below the throttling threshold permanently.
# Clamp maximum CPU frequency to maintain thermal equilibrium
echo 1800000 > /sys/devices/system/cpu/cpufreq/policy0/scaling_max_freq

5. Verification and Benchmarking

Developers validate thermal tuning using load testing and metric logging:

  1. Synthetic Stress Testing: Run continuous multi-threaded workloads using tools like stress-ng or real-world inference loops with ONNX Runtime or TensorFlow Lite.
  2. Telemetry Capture: Continuously poll thermal zones, governor states, and CPU core frequencies using sysfs or trace-cmd:
while true; do
    paste <(cat /sys/class/thermal/thermal_zone0/temp) \
          <(cat /sys/devices/system/cpu/cpufreq/policy0/scaling_cur_freq)
    sleep 0.5
done

A properly tuned thermal configuration produces a flat frequency line at the SBC's maximum sustainable thermal threshold, eliminating the oscillating "sawtooth" performance profile typical of untuned edge systems.
