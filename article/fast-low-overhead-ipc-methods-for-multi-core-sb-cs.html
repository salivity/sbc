Fast Low-Overhead IPC Methods for Multi-Core SBCs

On multi-core embedded single-board computers (SBCs), minimizing Inter-Process Communication (IPC) latency and CPU utilization is vital for real-time responsiveness and high data throughput. Traditional IPC mechanisms like network sockets, standard Unix pipes, and heavy message brokers introduce kernel transitions, context switching, and data copying overhead. This article details the primary low-overhead IPC mechanisms suited for multi-core embedded systems, explaining how shared memory structures, lockless algorithms, notification primitives, and asymmetric core frameworks achieve maximum performance.

1. POSIX Shared Memory (shm_open and mmap)

POSIX shared memory is the fastest standard IPC mechanism on Linux-based embedded SBCs. By mapping the same physical RAM pages into the virtual address spaces of multiple processes using shm_open() and mmap(), processes can exchange large datasets with zero memory copies.

  • How it reduces overhead: Data does not pass through the kernel buffer. Once the memory region is mapped, reads and writes occur directly at hardware memory bus speeds.
  • Best use case: High-bandwidth data pipelines, such as raw video frame streaming from a camera capture process to a computer vision inference process.

2. Lockless Ring Buffers (Queues)

While shared memory provides zero-copy access, coordinating reads and writes without introducing latency requires efficient synchronization. Lock-free Single-Producer Single-Consumer (SPSC) or Multiple-Producer Multiple-Consumer (MPMC) ring buffers deployed in shared memory eliminate the performance penalties of kernel-level mutexes.

  • How it reduces overhead: They rely on atomic operations (C11/C++11 atomics) and memory barriers rather than blocking system calls like pthread_mutex_lock(). This prevents thread preemption, context switching, and priority inversion.
  • Best use case: High-frequency, small-to-medium payload streaming (e.g., sensor telemetry, CAN bus message processing).

3. Lightweight Signatures and Notifications (eventfd and Futexes)

When a consumer process cannot spin-wait (poll) continuously due to power or CPU core constraints, a lightweight signaling mechanism is required alongside shared memory.

  • eventfd: A lightweight file descriptor designed for event notification. It consumes minimal kernel resources compared to standard pipes or signals and integrates seamlessly with epoll or poll event loops.
  • Futexes (Fast Userspace Mutexes): Futexes handle locking entirely in userspace for uncontended cases, entering the kernel only when a collision occurs and a process must sleep.
  • Best use case: Low-power event-driven architectures where processes sleep until new data is populated in shared memory.

4. UNIX Domain Sockets (AF_UNIX) with SOCK_DGRAM or SOCK_SEQPACKET

If strict zero-copy shared memory is too complex to implement safely, UNIX domain sockets provide a structured alternative that avoids the TCP/IP stack overhead entirely.

  • How it reduces overhead: UNIX domain sockets bypass network interface card (NIC) virtualization, packet checksumming, and routing logic, executing data transfers purely within kernel memory buffers.
  • Best use case: Command-and-control messaging, configuration updates, and modular microservice architectures on the same board.

5. OpenAMP and RPMsg for Heterogeneous Cores

Many modern embedded SBCs feature heterogeneous multi-core architectures (e.g., ARM Cortex-A application cores combined with ARM Cortex-M real-time cores). Standard Linux IPC cannot directly interact with bare-metal or RTOS environments on companion cores.

  • How it reduces overhead: The Open Asymmetric Multi-Processing (OpenAMP) framework uses Remote Processor Messaging (RPMsg) built on top of virtio and Inter-Processor Interrupts (IPI). It utilizes dedicated hardware-shared RAM regions and hardware mailboxes to signal state changes with sub-microsecond latency.
  • Best use case: Offloading real-time control loops, motor control, or deterministic I/O tasks to a microcontroller core while handling UI or networking on Linux.

Hardware and OS Optimizations for Embedded IPC

To extract maximum performance from any IPC mechanism on multi-core SBCs, combine them with these operating system tunings:

  • CPU Affinity (sched_setaffinity): Pin communicating processes to specific CPU cores. If processes share a high volume of data, pinning them to cores sharing an L2/L3 cache minimizes cache coherency bus traffic.
  • Real-Time Scheduling (SCHED_FIFO / SCHED_RR): Assign high-priority real-time scheduling classes to prevent IPC processing tasks from being preempted by background OS operations.
  • Huge Pages (Hugetlbfs): Use huge pages for shared memory segments to reduce Translation Lookaside Buffer (TLB) misses when dealing with large buffers.
