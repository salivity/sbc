How to Create Custom Systemd Services on SBCs

Configuring a custom systemd service allows software developers to run applications automatically on boot, manage background daemons, and ensure process recovery on Single Board Computers (SBCs) running Linux distributions like Raspberry Pi OS, Ubuntu, or Armbian. This guide covers the end-to-end process of preparing an application, defining a .service unit file, configuring automatic restarts, and managing the service lifecycle using systemctl.

1. Prepare Your Application

Before creating a service, verify that your executable or script runs independently without errors.

  1. Ensure the script has the correct shebang line (e.g., #!/usr/bin/env python3 or #!/bin/bash).
  2. Make the file executable: 
    chmod +x /home/user/app/my_script.py
  3. Note the absolute paths to both the executable/interpreter and the script.

2. Create the Systemd Unit File

systemd manages services through unit configuration files located in the /etc/systemd/system/ directory.

Create a new service file using root privileges:

sudo nano /etc/systemd/system/myapp.service

Add the following configuration:

[Unit]
Description=My Custom SBC Application
After=network.target

[Service]
Type=simple
User=user
WorkingDirectory=/home/user/app
ExecStart=/usr/bin/python3 /home/user/app/my_script.py
Restart=on-failure
RestartSec=5s
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target

Key Directives Explained:

  • After=network.target: Delays startup until networking components are initialized, preventing errors in network-dependent code.
  • User=: Runs the process under a non-root user account to adhere to least-privilege security practices.
  • WorkingDirectory=: Sets the runtime working directory for resolving relative file paths.
  • ExecStart=: Defines the exact command and absolute path to launch the application.
  • Restart=on-failure: Automatically restarts the program if it crashes or exits with a non-zero exit code.
  • WantedBy=multi-user.target: Ensures the service starts when the standard multi-user system state is reached during boot.

3. Set Permissions and Reload Systemd

Secure the unit file and notify systemd of the newly created service.

  1. Set the correct file permissions: 
    sudo chmod 644 /etc/systemd/system/myapp.service
  2. Reload the systemd manager configuration to register the changes: 
    sudo systemctl daemon-reload

4. Enable and Start the Service

Control the service lifecycle with systemctl:

  • Enable on boot: 
    sudo systemctl enable myapp.service
  • Start immediately: 
    sudo systemctl start myapp.service
  • Check runtime status: 
    sudo systemctl status myapp.service

5. Monitor and Debug Logs

systemd routes all standard output (stdout) and standard error (stderr) streams to journalctl.

  • View live streaming logs: 
    journalctl -u myapp.service -f
  • View logs from the current boot session: 
    journalctl -u myapp.service -b
