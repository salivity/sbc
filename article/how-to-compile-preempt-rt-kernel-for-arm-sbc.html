How to Compile PREEMPT_RT Kernel for ARM SBC

This guide outlines the complete process of cross-compiling a real-time Linux kernel using the PREEMPT_RT patch for a custom ARM-based single board computer (SBC). Achieving deterministic, low-latency performance on embedded ARM hardware requires obtaining the matching kernel and patch sources, setting up an appropriate cross-compilation toolchain, configuring the preemption model, building the kernel binaries and Device Tree Blobs (DTBs), and deploying the resulting artifacts to the target board.

Step 1: Prepare the Host Build Environment

Compiling directly on an embedded ARM board is often slow due to limited CPU and RAM resources. It is best practice to cross-compile on a high-performance x86_64 host running Linux.

Install the necessary build dependencies and the ARM cross-compiler:

sudo apt update
sudo apt install -y build-essential libncurses-dev bison flex libssl-dev \
    libelf-dev bc git wget u-boot-tools

Install the appropriate toolchain for your target architecture:

  • For 64-bit ARM (ARMv8 / AArch64): sudo apt install -y gcc-aarch64-linux-gnu g++-aarch64-linux-gnu
  • For 32-bit ARM (ARMv7 / armhf): sudo apt install -y gcc-arm-linux-gnueabihf g++-arm-linux-gnueabihf

Export environment variables for your build session (example shown for 64-bit ARM):

export ARCH=arm64
export CROSS_COMPILE=aarch64-linux-gnu-

Step 2: Download the Kernel Source and Matching RT Patch

The PREEMPT_RT patch must match the exact minor version of the Linux kernel source.

  1. Create a working directory:

    mkdir -p ~/rt-kernel-build && cd ~/rt-kernel-build

  2. Download your base kernel (either the mainline Linux kernel from kernel.org or your SBC vendor's kernel fork) and the corresponding PREEMPT_RT patch:

    # Example: Linux 6.1.70
wget https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.1.70.tar.xz
wget https://cdn.kernel.org/pub/linux/kernel/projects/rt/6.1/patch-6.1.70-rt21.patch.xz

  3. Extract the files:

    tar -xf linux-6.1.70.tar.xz
unxz patch-6.1.70-rt21.patch.xz

Step 3: Apply the PREEMPT_RT Patch

Navigate to the extracted kernel directory and apply the real-time patch:

cd linux-6.1.70
patch -p1 < ../patch-6.1.70-rt21.patch

Ensure no patch conflicts or failures (.rej files) are reported before proceeding.

Step 4: Configure the Real-Time Kernel

Start with your board vendor's default configuration (defconfig) or a baseline generic config, then modify it for real-time operation.

  1. Load the baseline configuration:

    make defconfig

    (Replace defconfig with your board-specific config file if provided by the vendor, e.g., make custom_sbc_defconfig).

  2. Open the kernel configuration menu:

    make menuconfig

  3. Modify the following settings for real-time behavior:

    • Enable Full Preemption:
      • Navigate to: General setup -> Preemption Model
      • Select: Fully Preemptible Kernel (Real-Time) (CONFIG_PREEMPT_RT=y)
    • Enable High-Resolution Timers:
      • Navigate to: General setup -> Timers subsystem
      • Ensure High Resolution Timer Support (CONFIG_HIGH_RES_TIMERS=y) is checked.
    • Optimize CPU Frequency Scaling:
      • Navigate to: Power management and ACPI options -> CPU Frequency scaling
      • Set Default CPUFreq governor to performance to eliminate latency spikes caused by CPU frequency changes.
    • Disable Conflicting Debugging and Power Features:
      • Disable CONFIG_SUSPEND and CONFIG_HIBERNATION if not needed.
      • Disable kernel debug options like CONFIG_PROVE_LOCKING or CONFIG_DEBUG_INFO to minimize overhead in production.

  4. Save the configuration and exit menuconfig.

Step 5: Compile Kernel, Modules, and Device Trees

Run the compilation using all available host CPU cores:

# For 64-bit ARM (arm64):
make -j$(nproc) Image modules dtbs

# For 32-bit ARM (arm):
# make -j$(nproc) zImage modules dtbs

After the build completes, the output files will be located in:

  • Kernel binary: arch/arm64/boot/Image (or arch/arm/boot/zImage)
  • Device Tree: arch/arm64/boot/dts/<vendor>/<board-name>.dtb

Step 6: Package and Deploy to the Target SBC

  1. Install Modules to a Staging Directory:

    mkdir -p ~/rt-kernel-build/modules_out
make modules_install INSTALL_MOD_PATH=~/rt-kernel-build/modules_out

  2. Transfer Files to the SBC: Transfer the compiled binaries, modules, and device tree blob to your target board via SSH/SCP or by mounting the SBC’s SD card/eMMC partitions:

    • Copy arch/arm64/boot/Image to the target board's /boot/ directory.
    • Copy arch/arm64/boot/dts/<vendor>/<board-name>.dtb to /boot/ or the designated bootloader partition.
    • Copy the contents of ~/rt-kernel-build/modules_out/lib/modules/<kernel-version>-rt/ to the target's /lib/modules/ directory.

  3. Update Bootloader Configuration: Ensure U-Boot or your SBC's boot configuration (such as extlinux.conf, boot.scr, or uEnv.txt) points to the new kernel image and device tree file.

Step 7: Verify Real-Time Functionality

Reboot the custom ARM board into the new kernel and verify that the PREEMPT_RT patch is active:

uname -a

The output should display PREEMPT_RT in the kernel description string, confirming that the real-time kernel is active:

Linux custom-arm-sbc 6.1.70-rt21 #1 SMP PREEMPT_RT ... aarch64 GNU/Linux

To evaluate real-time latency performance on the device, run cyclictest from the rt-tests suite under simulated load:

sudo apt install -y rt-tests
sudo cyclictest -m -p 99 -n -a -t -l 100000
