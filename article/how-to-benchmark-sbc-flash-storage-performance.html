How to Benchmark SBC Flash Storage Performance

Benchmarking the raw input/output (I/O) performance of flash storage on a single-board computer (SBC) requires testing throughput, IOPS (input/output operations per second), and latency while isolating storage hardware from system memory caching. This guide covers the essential command-line tools and methodologies developers use to evaluate microSD cards, eMMC modules, and NVMe SSDs connected to Linux-based SBCs.

Mitigating the Linux Page Cache

Accurate storage benchmarking requires bypassing the operating system's RAM cache. When write operations hit RAM instead of flash memory, reported speeds appear artificially high. Developers bypass this by:

  1. Using Direct I/O: Specifying flags that force processes to read from and write directly to the physical storage device.
  2. Dropping Caches: Manually clearing cached data between tests with the following command: 
    sync; echo 3 | sudo tee /proc/sys/vm/drop_caches

Method 1: Flexible I/O Tester (fio)

fio is the industry-standard benchmarking tool for Linux because it provides granular control over block sizes, queue depths, and thread counts.

1. Random 4K Read/Write Performance (IOPS)

Random 4K read and write speeds represent the most critical metric for general OS responsiveness, database queries, and small-file access on SBCs.

  • Random 4K Write: 
    fio --name=randwrite --ioengine=libaio --iodepth=16 --rw=randwrite --bs=4k --direct=1 --size=512M --numjobs=1 --runtime=60 --group_reporting --filename=testfile
  • Random 4K Read: 
    fio --name=randread --ioengine=libaio --iodepth=16 --rw=randread --bs=4k --direct=1 --size=512M --numjobs=1 --runtime=60 --group_reporting --filename=testfile

2. Sequential Read/Write Performance (Throughput)

Sequential speeds determine how fast the storage handles large continuous files, such as video streams or disk images.

  • Sequential Write (1MB Block Size): 
    fio --name=seqwrite --ioengine=libaio --iodepth=4 --rw=write --bs=1M --direct=1 --size=1G --numjobs=1 --runtime=60 --group_reporting --filename=testfile
  • Sequential Read (1MB Block Size): 
    fio --name=seqread --ioengine=libaio --iodepth=4 --rw=read --bs=1M --direct=1 --size=1G --numjobs=1 --runtime=60 --group_reporting --filename=testfile

Method 2: Quick Sanity Checks with dd

While dd lacks the advanced metrics of fio, it offers a quick method for measuring raw sequential write throughput without installing third-party utilities.

  • Write Test (Direct I/O): 
    dd if=/dev/zero of=temp_test bs=1M count=1024 oflag=direct status=progress
  • Read Test: Clear caches, then read the created file back into memory: 
    sync; echo 3 | sudo tee /proc/sys/vm/drop_caches
dd if=temp_test of=/dev/null bs=1M status=progress
  • Cleanup: 
    rm temp_test

Method 3: Hardware Read Testing with hdparm

hdparm provides a fast assessment of sequential read capabilities directly from the block device (such as /dev/mmcblk0 for SD/eMMC or /dev/nvme0n1 for NVMe).

sudo hdparm -tT /dev/mmcblk0
  • Cached Reads (-T): Measures read speed from the Linux page cache directly to CPU/RAM.
  • Buffered Disk Reads (-t): Measures the throughput of reads coming directly through the storage controller without cache assistance.

Key Metrics to Evaluate

  • Random 4K Read/Write IOPS: Higher numbers indicate smoother multitasking, faster boot times, and better database performance.
  • Sequential Throughput (MB/s): Indicates speed for streaming media, bulk file backups, and firmware flashing.
  • Latency (p95/p99): Reported by fio, 95th and 99th percentile latency reveals whether the storage medium suffers from micro-stutters or unpredictable I/O bottlenecks.
