Full Disk Encryption Performance on Low-Power SBCs

Enabling full disk encryption (FDE) on low-power single board computers (SBCs) provides essential data-at-rest protection, but it introduces noticeable performance trade-offs due to limited hardware resources. This article outlines the primary impacts of running FDE on resource-constrained devices, detailing how cryptographic operations affect CPU utilization, read/write speeds, latency, power draw, and thermal stability.

1. Elevated CPU Utilization

Low-power SBCs typically rely on energy-efficient ARM or RISC-V processors with limited processing power. When FDE is active, every read and write operation requires real-time encryption or decryption. On boards lacking dedicated cryptographic hardware extensions (such as ARMv8 Cryptography Extensions or AES-NI), the CPU must handle these algorithms entirely in software. This causes significant CPU spikes during routine disk operations, leaving fewer processing cycles available for user applications, background services, and system tasks.

2. Reduced Storage Read and Write Throughput

The most direct consequence of software-driven encryption is a drop in sequential and random I/O throughput. Even when paired with fast storage media like high-speed micro-SD cards, eMMC modules, or NVMe SSDs via PCIe, the maximum transfer speed becomes bottlenecked by the processor's ability to process the cipher blocks. Sequential read and write speeds can decrease by 30% to over 70% depending on the specific cipher, the storage bus speed, and the processor architecture.

3. Increased Latency and Longer Boot Times

Because the system must decrypt the root filesystem on the fly, system initialization and application startup times increase. Random I/O operations—common in database workloads and operating system logging—experience higher latency. This latency can cause noticeable sluggishness in responsive operations, such as serving web requests or launching heavy software packages.

4. Higher Power Consumption

Cryptographic operations force the CPU to run at higher clock frequencies for longer durations to process data transfers. This sustained processing directly increases the device's electrical power consumption. For battery-powered, solar, or remote edge deployments, the added power overhead can significantly reduce operational runtime and energy efficiency.

5. Thermal Throttling

Many low-power SBCs rely on passive cooling. The sustained CPU loads generated by intensive read/write operations under FDE generate extra heat. If the device reaches its thermal ceiling, the processor will automatically throttle its clock speed to prevent damage. This thermal throttling introduces a compounding performance penalty, drastically slowing down both the cryptographic operations and overall system performance.

6. Cipher Selection Impact

The severity of these trade-offs largely depends on the chosen encryption algorithm. Standard AES-XTS (e.g., AES-256) is highly demanding on hardware without native AES instructions. Opting for alternative ciphers optimized for software execution—such as Adiantum or ChaCha20-Poly1305—can significantly reduce CPU overhead and recover throughput on boards lacking hardware acceleration, though some performance penalty relative to unencrypted storage will always remain.
