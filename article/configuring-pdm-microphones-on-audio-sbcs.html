Configuring PDM Microphones on Audio SBCs

Pulse-density modulation (PDM) microphones are widely used in embedded audio projects for their high noise immunity, low cost, and small footprint. Configuring PDM microphones on an audio-focused single-board computer (SBC) requires interfacing the digital microphone hardware with the board's digital audio interface, modifying the kernel's device tree, configuring decimation filters to convert 1-bit PDM streams to multi-bit PCM, and setting up the audio subsystem for capture.

1. Hardware Pin Connections

PDM microphones transmit data over a two-wire digital interface: a clock line (CLK) driven by the SBC and a data line (DAT) driven by the microphone.

  • Clock (CLK): Connect to the SBC's PDM/I2S clock output pin.
  • Data (DAT): Connect to the SBC's PDM data input pin.
  • Channel Select (L/R or SEL): PDM microphones share a single data line for stereo capture. Tie this pin to Ground (GND) to transmit on the falling edge (Left channel) or to Power (VDD) to transmit on the rising edge (Right channel).
  • Power (VDD) and Ground (GND): Provide a stable voltage source (typically 1.8V or 3.3V) with decoupling capacitors placed close to the microphone.

2. Device Tree Configuration

Audio-focused SBCs rely on the Linux Device Tree to map peripherals to system drivers. To enable the PDM interface:

  1. Locate or Create a Device Tree Overlay: Define the pin multiplexing (pinmux) to assign the physical pins to the hardware PDM controller or digital microphone codec driver (such as dmic-codec).
  2. Define the Sound Card Node: Bind the PDM controller to the audio platform driver (ALSA System on Chip / ASoC).
  3. Specify Interface Properties: Define parameters such as supported sample rates, clock frequencies (typically between 1 MHz and 3.28 MHz), and channel counts.

A typical overlay snippet defines the generic dmic-codec node and links it via a simple-audio-card definition:

dmic_codec: dmic_codec {
    compatible = "dmic-codec";
    #sound-dai-cells = <0>;
};

sound {
    compatible = "simple-audio-card";
    simple-audio-card,name = "PDM-Mic-Array";
    simple-audio-card,dai-link@0 {
        format = "pdm";
        cpu {
            sound-dai = <&pdm_controller>;
        };
        codec {
            sound-dai = <&dmic_codec>;
        };
    };
};

Compile and apply the overlay to the board's boot configuration file (such as armbianEnv.txt or config.txt, depending on the platform).

3. Decimation and Digital Signal Processing

PDM produces a high-frequency, 1-bit oversampled stream that must be downsampled and filtered into standard Pulse-Code Modulation (PCM) audio (e.g., 16-bit or 24-bit at 48 kHz).

  • Hardware Decimation: If the SBC contains a dedicated PDM hardware module, the internal hardware filter handles decimation and filtering automatically with zero CPU overhead.
  • Software Decimation: If reading raw PDM data via a generic high-speed SPI or I2S port, developers must run a software decimation filter (such as a Cascaded Integrator-Comb / CIC filter) in userspace or via an ALSA plugin before processing the audio.

4. Audio Subsystem Configuration (ALSA)

Once the driver and device tree are loaded, verify that the Linux audio layer detects the hardware:

  1. List Capture Devices: Run arecord -l to confirm the PDM sound card appears in the list of recording devices.
  2. Set Mixer Controls: Use alsamixer or amixer to unmute the capture channels and set the digital capture volume.
  3. Configure Default Routing: If using a sound server like PipeWire or PulseAudio, set the PDM card as the default capture source in the configuration files or via tools like pactl or wpctl.

5. Testing and Validation

Verify proper functionality and signal integrity using ALSA utilities:

  • Record a Test Sample: 
    arecord -D hw:CARD_INDEX,DEV_INDEX -f S16_LE -r 48000 -c 2 -d 5 test.wav
  • Inspect Audio Output: Play back the file using aplay or inspect the waveform with an audio analysis tool to ensure there is no channel cross-talk, clock jitter noise, or signal clipping.
