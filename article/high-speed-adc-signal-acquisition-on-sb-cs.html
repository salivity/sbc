High-Speed ADC Signal Acquisition on SBCs

Acquiring high-speed analog signals on a single board computer (SBC) requires augmenting the host system with dedicated Analog-to-Digital Converter (ADC) expansion boards. Because standard SBCs lack the native processing bandwidth and low-latency input pins needed for megasample-per-second (MSPS) or gigasample-per-second (GSPS) sampling, these specialized add-on boards handle signal conditioning, precision sampling, and high-throughput data buffering. The digitized data is then routed to the SBC using high-bandwidth communication interfaces like PCIe, high-speed SPI, or FPGA-assisted bridging, allowing the SBC to perform real-time digital signal processing, visualization, or storage without losing critical data points.

The Architecture of Dedicated ADC Expansion Boards

A dedicated high-speed ADC expansion board functions as a standalone data acquisition front-end. Its architecture is engineered to isolate the sensitive analog domain from the high-frequency electrical noise generated by the SBC's processor and power supply.

  • Analog Front-End (AFE): Before conversion, incoming analog signals pass through conditioning circuits. These include low-noise operational amplifiers (op-amps) for gain scaling, impedance matching networks, and passive or active anti-aliasing low-pass filters to prevent frequency folding.
  • ADC Core: The converter itself—often utilizing Successive Approximation Register (SAR), Flash, or Pipelined architectures—samples the conditioned signal at rates ranging from several MSPS to several GSPS with resolutions typically between 8 and 16 bits.
  • Onboard Buffering (FIFO / FPGA): High-speed ADCs generate data streams faster than standard SBC GPIO pins can process. Dedicated expansion boards integrate Field Programmable Gate Arrays (FPGAs), CPLDs, or dedicated FIFO (First-In, First-Out) memory to temporarily queue raw sample blocks, manage sample clocking, and reduce jitter.

High-Throughput Interconnects

Transferring digitized data from the expansion board to the SBC processor requires high-bandwidth, low-latency communication buses:

  1. High-Speed SPI / QSPI: Suitable for moderate speeds (up to several MSPS). Quad-SPI increases throughput by utilizing four data lines simultaneously.
  2. PCI Express (PCIe): Used for extremely high data rates (tens of MSPS to GSPS). PCIe lanes provide direct, low-latency access to the SBC’s memory bus.
  3. Parallel / LVDS (Low-Voltage Differential Signaling): Often routed into an FPGA mezzanine card (FMC) or high-density expansion header before being serialized for the host processor.
  4. USB 3.0 / USB-C: High-speed external conversion boards leverage USB 3.0 SuperSpeed endpoints (up to 5 Gbps) to stream bulk ADC data directly to the SBC.

Mitigating CPU Bottlenecks with DMA

If an SBC’s Central Processing Unit (CPU) had to handle every incoming sample via standard software interrupts, the system would immediately suffer from buffer overruns and dropped samples.

To overcome this, high-speed ADC expansion systems rely on Direct Memory Access (DMA):

  • The ADC or its onboard controller writes digitized samples directly into the SBC’s system RAM without continuous CPU intervention.
  • Circular buffers (ring buffers) are allocated in the host memory. As the ADC fills one segment of the buffer, a single interrupt notifies the operating system, allowing the application to process the block of samples in bulk using SIMD (Single Instruction, Multiple Data) or GPU acceleration.

Software Drivers and Real-Time Acquisition

Capturing high-speed signals reliably requires low-latency software integration:

  • Kernel Drivers and the IIO Subsystem: Under Linux-based SBCs, high-speed ADCs typically integrate with the Industrial I/O (IIO) subsystem. The IIO framework offers standardized user-space interfaces, hardware trigger support, and buffered read mechanisms optimized for high throughput.
  • Real-Time Kernels: Standard OS scheduling jitter can cause processing delays. Applying a real-time kernel patch (such as PREEMPT_RT for Linux) ensures deterministic processing of incoming ADC buffers, preventing buffer overflow during continuous data streaming.
