Configure Thermal Trip Points in Linux for Custom SBCs

Configuring thermal trip points in the Linux kernel for a custom single board computer (SBC) involves defining thermal zones, trip temperatures, and cooling device behaviors within the Device Tree (DTS). This guide explains how to structure the Device Tree thermal nodes, define different trip types such as active, passive, and critical, bind them to cooling mechanisms like Dynamic Voltage and Frequency Scaling (DVFS) or PWM fans, and verify the configuration at runtime using sysfs.

Understanding the Linux Thermal Framework in Device Tree

The Linux kernel thermal framework monitors on-chip temperature sensors (TSCs/thermal sensors) and triggers mitigation actions based on predefined thresholds known as trip points. On custom ARM/ARM64 and RISC-V SBCs, this behavior is declared under the thermal-zones node in your board's Device Tree source (.dts or .dtsi) file.

A complete thermal configuration consists of three primary components:

  1. Thermal Sensor (thermal-sensors): The hardware sensor providing temperature readings.
  2. Trips (trips): Temperature thresholds that trigger specific actions.
  3. Cooling Maps (cooling-maps): Associations connecting trip points to cooling devices (CPUs, GPUs, fans).

Step-by-Step Device Tree Configuration

1. Define the Thermal Zone and Sensor Reference

Open your custom board's DTS file and define the thermal-zones block. Ensure your SoC's internal thermal sensor driver is enabled in the kernel config (e.g., CONFIG_ROCKCHIP_THERMAL, CONFIG_IMX_SCU_THERMAL).

/ {
    thermal-zones {
        cpu_thermal: cpu-thermal {
            polling-delay-passive = <250>; /* Polling interval in ms when cooling */
            polling-delay = <1000>;         /* Polling interval in ms when idle */
            thermal-sensors = <&tsadc 0>;   /* Reference to your hardware sensor */

            trips {
                /* Trip points defined here */
            };

            cooling-maps {
                /* Bindings to cooling devices defined here */
            };
        };
    };
};

2. Define Thermal Trip Points

Under the trips subnode, create nodes for each required threshold. Temperatures are specified in milli-Celsius (e.g., 75000 equals 75°C).

trips {
    cpu_alert: cpu-alert {
        temperature = <70000>;
        hysteresis = <2000>;
        type = "passive";
    };

    fan_active: fan-active {
        temperature = <80000>;
        hysteresis = <5000>;
        type = "active";
    };

    cpu_crit: cpu-crit {
        temperature = <95000>;
        hysteresis = <0>;
        type = "critical";
    };
};

Trip Types:

  • passive: Throttles performance (typically reducing CPU/GPU operating frequency) to prevent further heating without hardware-driven external cooling.
  • active: Engages active cooling devices such as a PWM-controlled fan.
  • hot: Notifies user-space via a uevent without kernel-level thermal governor intervention.
  • critical: Triggers an immediate hardware or software shutdown to prevent silicon damage.

3. Bind Trip Points to Cooling Devices

Under cooling-maps, pair each trip point with a cooling device (e.g., CPU frequency states via CPUFreq or a PWM fan).

cooling-maps {
    map0 {
        trip = <&cpu_alert>;
        cooling-device = <&cpu0 THERMAL_NO_LIMIT THERMAL_NO_LIMIT>;
        contribution = <1024>;
    };

    map1 {
        trip = <&fan_active>;
        cooling-device = <&fan0 1 3>; /* Fan states: minimum state 1, maximum state 3 */
    };
};

Note: Ensure the CPU nodes have #cooling-cells = <2>; defined to allow CPUFreq to act as a cooling device.

Kernel Configuration

Ensure the necessary thermal governors are compiled into your kernel (.config):

  • CONFIG_THERMAL=y
  • CONFIG_THERMAL_OF=y
  • CONFIG_THERMAL_GOV_STEP_WISE=y (commonly used for passive DVFS cooling)
  • CONFIG_THERMAL_GOV_FAIR_SHARE=y
  • CONFIG_CPU_THERMAL=y (allows CPU frequency scaling as a cooling device)
  • CONFIG_THERMAL_GOV_USER_SPACE=y (if handling thermal states in userspace)

Verifying Thermal Trip Points via Sysfs

After compiling the Device Tree blob (.dtb) and booting the custom SBC, verify that the thermal subsystem is operational through /sys/class/thermal/:

  1. List thermal zones and read current temperature:

    cat /sys/class/thermal/thermal_zone0/type
cat /sys/class/thermal/thermal_zone0/temp

  2. Check configured trip points:

    cat /sys/class/thermal/thermal_zone0/trip_point_0_temp
cat /sys/class/thermal/thermal_zone0/trip_point_0_type

  3. Modify trip points at runtime for testing (requires root permissions):

    echo 65000 > /sys/class/thermal/thermal_zone0/trip_point_0_temp

Simulate load using a tool like stress-ng to verify that CPU frequency drops when the passive threshold is reached and that the system shuts down safely if the critical temperature is triggered.
