Inter-Board Communication Protocols for SBCs

Connecting two Single Board Computers (SBCs) requires choosing a communication protocol that balances speed, distance, wiring complexity, and software overhead. This article outlines the most common protocols used for inter-board communication between SBCs—ranging from low-level serial interfaces like UART, SPI, and I2C to high-bandwidth solutions like Ethernet and USB—helping you determine the right method for your multi-board architecture.

1. Ethernet (TCP/IP and UDP)

Ethernet is the most versatile and scalable method for connecting two SBCs. It supports standard network protocols, making it ideal for distributed computing, robotics, and multimedia sharing.

  • Characteristics: High bandwidth (100 Mbps to 1+ Gbps), long transmission distances (up to 100 meters), and built-in error checking.
  • Common Use Cases: Streaming video, distributed processing, REST APIs, MQTT messaging, and Robot Operating System (ROS) node communication.
  • How It Works: SBCs can be linked directly using a standard Ethernet cable (modern PHYs support auto-MDIX, eliminating the need for crossover cables) or via a network switch, communicating over standard sockets (TCP/UDP).

2. UART (Universal Asynchronous Receiver-Transmitter)

UART is a straightforward, point-to-point asynchronous serial protocol requiring only two data lines and a common ground.

  • Characteristics: Point-to-point only, moderate speeds (typically 9600 baud to 1.5+ Mbaud), simple software implementation.
  • Wiring: TX (Transmit) on Board A connects to RX (Receive) on Board B, RX on Board A connects to TX on Board B, plus a common Ground.
  • Common Use Cases: Command-and-control messaging, heartbeat signals, simple text/telemetry logging, and headless terminal access.

3. SPI (Serial Peripheral Interface)

SPI is a high-speed, synchronous, full-duplex protocol primarily used for short-distance inter-chip and inter-board transfers.

  • Characteristics: Very high speeds (often exceeding 10–50 MHz), synchronous clock, master-slave architecture.
  • Wiring: Requires four lines: MOSI (Master Out Slave In), MISO (Master In Slave Out), SCK (Serial Clock), and CS/SS (Chip Select).
  • Common Use Cases: Transferring bulk binary data, sensor arrays, or real-time control packets where one SBC acts as the primary controller and the other as a dedicated coprocessor.

4. I2C (Inter-Integrated Circuit)

I2C is a synchronous, multi-master/multi-slave, two-wire bus system designed for short-range communication.

  • Characteristics: Low-to-moderate speed (standard 100 kHz, fast mode 400 kHz, high speed up to 3.4 MHz), uses only two wires with pull-up resistors.
  • Wiring: SDA (Serial Data) and SCL (Serial Clock), plus a common Ground.
  • Common Use Cases: Low-frequency sensor data sharing, configuration registers, and basic state synchronization across adjacent boards.

5. CAN Bus (Controller Area Network)

Originally developed for the automotive industry, CAN bus is an ultra-reliable, message-based differential protocol suited for electrically noisy environments.

  • Characteristics: High fault tolerance, differential signaling (CAN_H and CAN_L), built-in arbitration and error handling, operational over long distances (up to 1 km at reduced speeds).
  • Hardware Requirement: Typically requires a CAN controller and transceiver (e.g., MCP2515 via SPI).
  • Common Use Cases: Robotics, industrial automation, and automotive projects requiring deterministic message delivery.

6. USB (Universal Serial Bus)

SBCs can communicate directly over USB using specific configurations such as USB OTG (On-The-Go) / Gadget Mode or via dedicated USB-to-UART bridge adapters.

  • Characteristics: High throughput (USB 2.0/3.0 speeds), hot-pluggable, flexible protocol emulation (e.g., Ethernet-over-USB via RNDIS/CDC-Ether or serial-over-USB via CDC-ACM).
  • Common Use Cases: High-speed data links where an Ethernet port is unavailable or reserved for external networks.
