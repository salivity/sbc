How to Multiplex MIPI CSI Cameras on an SBC

Multiplexing a Camera Serial Interface (MIPI CSI-2) across multiple image sensors on a single board computer (SBC) allows developers to connect multiple cameras to hardware with limited native CSI ports. This architecture is achieved by utilizing physical high-speed switches, I2C bus routing, MIPI virtual channels, or dedicated bridge processors to manage data flow. This article breaks down the hardware mechanisms, control protocols, and software requirements necessary to multiplex camera sensors into a single CSI-2 receiver interface.

1. High-Speed Physical Lane Multiplexing

The most common method for basic multi-camera setups involves using high-speed analog differential switches (such as MIPI D-PHY switches).

  • Signal Routing: A MIPI CSI-2 interface consists of differential pairs for high-speed clock and data lanes. An analog switch acts as a hardware multiplexer, routing the high-speed differential lines from two or more camera modules into a single CSI connector on the SBC.
  • Control Lines: The SBC toggles General Purpose Input/Output (GPIO) pins to switch the hardware path from one sensor to another.
  • Time-Division Operation: Because the physical lanes are directly switched, this method operates via time-division multiplexing. Only one camera sensor can transmit video frames to the processor at any given instant.

2. Control Plane Switching via I2C Multiplexers

Image sensors require a low-speed control plane, typically an I2C or I3C bus, for configuration, exposure control, and register access.

  • Address Collision Prevention: Most identical image sensors share the same hardcoded I2C address. To communicate with individual sensors independently, an I2C multiplexer (such as a PCA9548A or TCA9548A) is placed between the SBC and the sensors.
  • Channel Selection: The SBC sends a command to the I2C multiplexer to select the desired downstream channel before initializing or adjusting sensor settings. This enables isolated control of each sensor without bus conflicts.

3. Virtual Channel Multiplexing with Bridge Chips or FPGAs

When simultaneous multi-camera capture is required over a single physical CSI port, hardware bridge chips or FPGAs are used to interleave streams using MIPI Virtual Channels (VC).

  • Virtual Channel IDs: The MIPI CSI-2 specification supports up to 16 Virtual Channels. Each data packet contains a Virtual Channel Identifier (VC ID) in its header.
  • Frame Aggregation: Multiple sensors output continuous streams to an intermediate bridge IC, FPGA, or SerDes deserializer (such as GMSL or FPD-Link hubs). The bridge receives the parallel streams, assigns a unique VC ID to each sensor's packets, and outputs an aggregated, high-bandwidth CSI-2 stream to the SBC's receiver port.
  • Processor De-interleaving: The SBC’s Image Signal Processor (ISP) and MIPI receiver separate the incoming stream by VC ID, processing each video feed simultaneously in memory.

4. Software and Driver Implementation

To properly utilize a multiplexed CSI bus, the SBC's operating system must coordinate hardware switching and video pipeline configuration.

  • Device Tree Configuration: On Linux-based SBCs, the Device Tree defines the multiplexer nodes, I2C switch sub-buses, and camera sensor endpoints within the Video4Linux2 (V4L2) framework.
  • State Management: When using physical switches, the driver must account for switching latency, clock synchronization, and sensor wake-up times. Switching between cameras often requires resetting the CSI-2 receiver pipeline and loading cached exposure and white balance parameters to avoid frame drops or corruption.
