EtherCAT Master Stacks for Single Board Computers

Deploying an industrial EtherCAT master on a Single Board Computer (SBC) requires a combination of real-time operating systems and optimized EtherCAT master software stacks. This article explores the primary open-source and commercial software stacks available for embedded SBC platforms—such as Raspberry Pi, BeagleBone, and x86-based boards—enabling engineers to achieve deterministic, low-latency control for industrial automation and robotics.

Real-Time Foundation: RTOS and RT-Linux

Before selecting an EtherCAT master stack, the host operating system must guarantee deterministic task execution. Standard general-purpose operating systems introduce jitter that compromises EtherCAT synchronization.

  • Linux with PREEMPT_RT: Converts Linux into a real-time system by making kernel primitives preemptible. It is the most common foundation for open-source master stacks on ARM and x86 SBCs.
  • Xenomai / RTAI: Dual-kernel architectures that run a real-time microkernel alongside the standard Linux kernel, providing ultra-low jitter for demanding applications.
  • Dedicated RTOS: Systems like FreeRTOS, Zephyr, or VxWorks used on bare-metal or dual-core SBC configurations.

Open-Source EtherCAT Master Stacks

1. SOEM (Simple Open EtherCAT Master)

SOEM is a lightweight, widely adopted C library designed for embedded applications.

  • Architecture: Runs primarily in user space using standard raw socket interfaces (AF_PACKET) or custom network drivers.
  • Portability: Highly portable across standard Linux, PREEMPT_RT, RTOS environments, and bare-metal platforms.
  • Performance: Capable of sub-millisecond cycle times when paired with PREEMPT_RT and high-priority POSIX threads.
  • Best Used For: Custom embedded robotics, ROS/ROS 2 integration (via ethercat_grant or ROS EtherCAT wrappers), and lightweight ARM-based SBC projects.

2. IgH EtherCAT Master (EtherLab)

The IgH EtherCAT Master is implemented as a native Linux kernel module, delivering high performance and low jitter.

  • Architecture: Operates within the kernel space, utilizing dedicated, optimized network device drivers (e.g., modified Intel e1000e or r8169 drivers) alongside a generic driver fallback.
  • Performance: Offers lower latency and jitter compared to user-space stacks because it bypasses generic network stack overhead.
  • Distributed Clocks (DC): Strong built-in support for Distributed Clocks to synchronize slave devices with high precision.
  • Best Used For: Linux-based industrial controllers requiring hard real-time determinism on x86 or ARM platforms with supported network interfaces.

Commercial EtherCAT Master Stacks

1. Acontis EC-Master

Acontis EC-Master is an industry-standard commercial stack specifically optimized for embedded and real-time operating systems.

  • Features: Provides hard real-time capabilities with zero copy, minimal CPU overhead, and extensive diagnostics.
  • Platform Support: Supports Linux (PREEMPT_RT, Xenomai), Windows, VxWorks, QNX, and bare-metal environments on ARM Cortex-A architectures and x86 SBCs.
  • Performance: Easily achieves cycle times under 250 microseconds with sub-microsecond jitter when combined with supported dedicated network controllers.

2. CODESYS Control SoftPLC

CODESYS offers an installable runtime environment for various SBCs, such as the Raspberry Pi or industrial ARM boards.

  • Features: Includes an integrated IEC 61131-3 PLC environment, motion control libraries, and an EtherCAT master configurator.
  • Usability: Simplifies configuration via a visual IDE rather than manual code orchestration.
  • Best Used For: Rapid prototyping and commercial control applications where a full SoftPLC paradigm is required on low-cost hardware.

3. Kithara RealTime Suite

A modular commercial real-time extension suitable for industrial PC and x86 SBC deployments.

  • Features: Combines real-time communication modules with an EtherCAT Master supporting Distributed Clocks, high-speed cycle times, and slave hot-plugging.
  • Best Used For: x86-based SBCs requiring integrated hardware control, vision processing, and EtherCAT master functions.

Hardware and Network Considerations for SBCs

To achieve minimal latency and jitter regardless of the chosen software stack:

  • Ethernet Controller: Dedicated Ethernet MACs connected directly to the processor internal bus (PCIe or internal SoC bus) are essential. Avoid USB-to-Ethernet converters, as USB introduces non-deterministic packet delays.
  • Distributed Clocks (DC): Ensure the chosen network interface and driver accurately handle the transmission of synchronization frames to maintain sub-microsecond synchronization among slave nodes.
  • CPU Pinning and Isolation: Isolate CPU cores using the isolcpus Linux kernel parameter to dedicate specific cores exclusively to the EtherCAT communication thread.
