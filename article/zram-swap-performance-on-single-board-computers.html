ZRAM Swap Performance on Single Board Computers

Using ZRAM as swap storage significantly enhances the multitasking capabilities and responsiveness of memory-constrained single-board computers (SBCs) like the Raspberry Pi. By creating a compressed block device within the existing physical RAM, ZRAM trades a minor amount of CPU overhead to virtually expand usable memory, eliminate slow flash storage bottlenecks, and prevent system lockups caused by memory exhaustion.

What ZRAM Does in an SBC

ZRAM allocates a portion of the system's volatile memory to serve as a compressed swap device. When the Linux kernel needs to swap out inactive memory pages, it compresses them and stores them in this designated RAM space rather than writing uncompressed data to a physical drive. Typically, algorithms like LZ4 or ZSTD can compress memory data by a factor of 2:1 or 3:1, effectively turning 1 GB of physical RAM into roughly 1.5 GB to 2 GB of effective capacity.

The CPU Overhead vs. Memory Trade-Off

The primary cost of ZRAM is processor usage. The SBC's CPU must compress data when writing to swap and decompress it when reading data back.

  • CPU Impact: Modern ARM processors found in SBCs handle compression algorithms like LZ4 extremely fast. The CPU utilization rarely exceeds a negligible fraction for typical desktop or background workloads.
  • Throughput Benefit: RAM-to-RAM data transfers with compression are substantially faster than reading and writing uncompressed data to external storage. Even with the CPU compression overhead, ZRAM operations occur in microseconds, whereas flash I/O can take milliseconds.

Elimination of Flash Storage Bottlenecks

Standard SBC storage media, such as MicroSD cards and budget eMMC modules, have poor random read and write speeds. Using these media for traditional swap causes severe system freezes (thrashing) when memory runs low.

  • Lower Latency: ZRAM operates at memory bus speeds, avoiding the severe I/O wait times that freeze the user interface.
  • Extended Storage Lifespan: Flash memory degrades with repeated writes. Traditional swap files rapidly consume the write endurance of MicroSD cards. ZRAM keeps all swap writes in volatile memory, preventing flash wear.

Preventing Out-of-Memory (OOM) Crashes

On devices with 512 MB to 2 GB of RAM, running a modern web browser or compiling software quickly leads to Out-of-Memory (OOM) errors. Without swap, the kernel terminates active processes to free memory. With standard swap on an SD card, the system often locks up entirely. ZRAM provides a stable buffer that allows these memory-heavy tasks to complete smoothly without crashing the system.

Compression Algorithm Selection

The choice of compression algorithm directly impacts the performance balance on an SBC:

  • LZ4: The standard and recommended choice for low-power SBCs. It features low CPU overhead and high decompression speeds, making it ideal for weaker single-core or quad-core processors.
  • ZSTD: Offers higher compression ratios (saving more memory) at the cost of higher CPU utilization. This is best suited for modern quad-core SBCs running memory-intensive workloads where maximum RAM expansion is required.

Summary

For low-memory single-board computers, the performance benefits of ZRAM far outweigh the CPU compression costs. It prevents system thrashing, protects flash storage from write degradation, and allows low-RAM hardware to handle heavier workloads smoothly.
