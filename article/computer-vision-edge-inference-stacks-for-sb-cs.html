Computer Vision Edge Inference Stacks for SBCs

Deploying computer vision on single-board computers (SBCs) requires lightweight, highly optimized software stacks that maximize limited CPU, GPU, and NPU resources. This article outlines the most commonly used inference runtimes, hardware-specific acceleration toolkits, and image processing libraries that form the modern computer vision software pipeline on edge devices.

1. General-Purpose Lightweight Runtimes

  • TensorFlow Lite (TFLite): Designed specifically for mobile and edge devices, TFLite is a standard choice for ARM-based SBCs like the Raspberry Pi. It reduces binary size, supports int8 and float16 quantization, and leverages hardware acceleration via delegates (such as XNNPACK for CPU acceleration or the GPU delegate).
  • ONNX Runtime: A flexible, cross-platform inference engine developed by Microsoft. It allows developers to export models trained in PyTorch or TensorFlow into the Open Neural Network Exchange (ONNX) format. ONNX Runtime uses Execution Providers (such as OpenVINO, TensorRT, or CPU/XNNPACK) to map models directly to the host SBC's hardware capabilities.
  • PyTorch Mobile / ExecuTorch: PyTorch’s native solution for running models on resource-constrained devices. ExecuTorch is designed to provide modular, low-overhead execution for deep learning models across various edge architectures without requiring heavy runtime dependencies.

2. Vendor-Specific Acceleration Stacks

Most SBCs equipped with specialized AI accelerators (NPUs or integrated GPUs) require dedicated vendor software stacks to achieve real-time performance:

  • NVIDIA JetPack and TensorRT: For the NVIDIA Jetson platform (e.g., Jetson Orin Nano, Jetson Nano), JetPack includes the OS, CUDA, cuDNN, and TensorRT. TensorRT optimizes network layers, precision (INT8/FP16), and memory allocation specifically for NVIDIA GPUs.
  • Rockchip RKNN SDK: Popular on modern ARM SBCs featuring Rockchip processors with built-in NPUs (e.g., RK3588, RK3566). The RKNN-Toolkit converts Caffe, TensorFlow, PyTorch, and ONNX models into .rknn binaries, allowing developers to offload vision models directly to the hardware NPU.
  • Intel OpenVINO: Optimized for Intel processors, integrated GPUs, and specialized vision processing units (VPUs). While native to x86-based SBCs, OpenVINO also provides ARM Linux support for deploying optimized vision inference on heterogenous compute engines.
  • Hailo Software Suite: Used when pairing SBCs with M.2 or PCIe Hailo AI acceleration modules (such as on the Raspberry Pi AI Kit). The Hailo Dataflow Compiler converts models to execute natively on the low-power Hailo NPU.

3. Vision Processing and Pipeline Frameworks

An inference engine must be paired with software that handles video capture, decoding, preprocessing, and display:

  • OpenCV: The foundational computer vision library used across virtually all SBCs. It manages camera input, color space conversions, resizing, and bounding-box rendering. OpenCV also contains its own cv::dnn module, which can directly execute pre-trained models.
  • GStreamer: A multimedia framework used to build complex, low-latency video streaming pipelines. It is often combined with hardware decoders to process high-resolution video feeds before passing frames to the inference engine.
  • NVIDIA DeepStream: An end-to-end analytical pipeline manager built on top of GStreamer for Jetson devices, optimizing multi-camera video ingestion, inference, tracking, and metadata output.

Choosing the Right Stack

  • For Standard ARM SBCs (e.g., Raspberry Pi 4/5 with CPU only): TFLite or ONNX Runtime paired with OpenCV and XNNPACK.
  • For SBCs with Dedicated NPUs (e.g., Orange Pi 5, Radxa Rock 5): Vendor runtimes like the RKNN SDK or HailoRT for hardware offloading.
  • For GPU-Centric SBCs (e.g., NVIDIA Jetson): TensorRT integrated with DeepStream or OpenCV for maximum frames-per-second throughput.
