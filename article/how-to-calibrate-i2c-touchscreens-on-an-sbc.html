How to Calibrate I2C Touchscreens on an SBC

Calibrating an I2C-connected touch controller on a Single Board Computer (SBC) involves verifying hardware communication, capturing raw coordinate data, and applying a mathematical transformation to align touch points with the display. This guide covers the end-to-end technical process developers use to configure, test, and persist touchscreen calibration across Linux environments on SBCs such as Raspberry Pi, BeagleBone, or custom embedded boards.

1. Verify I2C Bus Communication and Driver Binding

Before software calibration, ensure the kernel properly detects the touch controller (such as Goodix, FocalTech, or Ilitek ICs) over the I2C bus.

  1. Scan the I2C Bus: Use i2c-tools to confirm the device responds at its designated I2C address: 
    sudo i2cdetect -y <bus_number>
    A response (or UU indicating an active driver) confirms electrical connectivity.
  2. Verify the Input Device Node: Ensure the Linux input subsystem (evdev) creates an event node: 
    cat /proc/bus/input/devices
    Look for the touch controller name and its assigned /dev/input/eventX path.
  3. Test Raw Events: Run evtest to ensure hardware interrupts and coordinate events are firing: 
    sudo evtest /dev/input/eventX
    Touching the screen should stream ABS_MT_POSITION_X and ABS_MT_POSITION_Y values.

2. Perform Touch Calibration

The method used to calculate coordinate offsets depends on whether the SBC runs an X11 display server, Wayland, or a raw frame-buffer environment.

For X11 Environments

  1. Run xinput_calibrator: Install and launch the utility: 
    sudo apt-get install xinput-calibrator
xinput_calibrator
  2. Collect Data Points: Tap the four crosshairs displayed on the screen. The tool computes the axis inversion, swap flags, and coordinate offsets, outputting an xorg.conf configuration snippet.

For Wayland Environments (e.g., Weston)

Wayland compositors handle input via libinput. Use the built-in Weston calibrator:

weston-touch-calibrator /sys/class/input/eventX

3. Calculate and Apply the Coordinate Transformation Matrix

Modern Linux touch stacks rely on libinput and a 3x3 affine transformation matrix (represented as a 9-element array) to scale, translate, and rotate touch inputs:

\[\begin{bmatrix} X_{screen} \\ Y_{screen} \\ 1 \end{bmatrix} = \begin{bmatrix} c_0 & c_1 & c_2 \\ c_3 & c_4 & c_5 \\ 0 & 0 & 1 \end{bmatrix} \begin{bmatrix} X_{raw} \\ Y_{raw} \\ 1 \end{bmatrix}\]

Common pre-calculated values for standard screen rotations include:

  • Default (No Rotation): 1 0 0 0 1 0 0 0 1
  • 90° Clockwise: 0 1 0 -1 0 1 0 0 1
  • 180° Inverted: -1 0 1 0 -1 1 0 0 1
  • 270° Clockwise: 0 -1 1 1 0 0 0 0 1

To temporarily test a matrix in X11:

xinput set-prop "<Device_Name>" "Coordinate Transformation Matrix" 0 -1 1 1 0 0 0 0 1

4. Make Calibration Persistent

To preserve calibration settings across reboots, apply the configuration at the Udev, X11, or Device Tree level.

Method A: Udev Rules (Recommended for libinput & Wayland)

Create a custom rule file at /etc/udev/rules.d/99-touchscreen.rules:

ENV{ID_INPUT_TOUCHSCREEN}=="1", ATTRS{name}=="<Controller_Name>", ENV{LIBINPUT_CALIBRATION_MATRIX}="1 0 0 0 1 0 0 0 1"

Reload Udev rules to apply:

sudo udevadm control --reload-rules && sudo udevadm trigger

Method B: X11 Configuration Files

Save the output from xinput_calibrator to /etc/X11/xorg.conf.d/99-calibration.conf:

Section "InputClass"
    Identifier      "calibration"
    MatchProduct    "<Controller_Name>"
    Option          "TransformationMatrix" "1 0 0 0 1 0 0 0 1"
EndSection

Method C: Device Tree (DTS) Adjustments (Embedded Linux / Yocto)

For headless or embedded configurations using direct framebuffers, define calibration properties directly inside the I2C node in your device tree:

&i2c1 {
    touchscreen@5d {
        compatible = "goodix,gt911";
        reg = <0x5d>;
        touchscreen-size-x = <1024>;
        touchscreen-size-y = <600>;
        touchscreen-inverted-x;
        touchscreen-swapped-x-y;
    };
};

Recompile the device tree blob (DTB) and deploy it to the boot partition.
