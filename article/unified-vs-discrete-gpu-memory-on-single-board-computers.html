Unified vs Discrete GPU Memory on Single Board Computers

Single Board Computers (SBCs) rely on distinct memory bus architectures depending on whether they utilize unified memory with an integrated graphics processor or dedicated memory with a discrete GPU. This article breaks down the physical, structural, and performance differences between unified memory architecture (UMA) and discrete GPU (dGPU) memory systems on SBC platforms, highlighting how bus topologies impact bandwidth, latency, and power efficiency.

Unified Memory Bus Architecture in SBCs

In a unified memory architecture, typical of integrated System-on-Chips (SoCs) like the Broadcom BCM2711 or Rockchip RK3588, the CPU and GPU share a single physical pool of system RAM (often LPDDR4/LPDDR5).

  • Shared System Bus: The CPU, GPU, and other accelerators communicate with system memory over an internal high-bandwidth Network-on-Chip (NoC) or crossbar interconnect (such as ARM AMBA AXI).
  • Zero-Copy Access: Because memory is physically shared, the GPU can access data structures created by the CPU without explicit data duplication over a secondary bus, reducing software-level transfer overhead.
  • Bandwidth Contention: Both the CPU and GPU compete for the same physical memory bus width (typically 32-bit or 64-bit on standard SBCs). High-demand graphical tasks or compute workloads can saturate the bus, creating memory bottlenecks for the CPU.
  • PCB Simplicity: The memory bus routes directly between the SoC and the onboard LPDDR chips, minimizing trace length, signal degradation, and board layer requirements.

Discrete GPU Memory Bus Architecture in SBCs

Some advanced SBCs interface with discrete GPUs via expansion interfaces (such as PCIe lanes via M.2 or PCIe slots) or integrate an onboard discrete graphics controller with its own dedicated Video RAM (VRAM).

  • Dedicated Memory Bus: The discrete GPU possesses an isolated, dedicated memory bus directly connecting the GPU die to its VRAM (such as GDDR6). This bus operates independently of the system memory bus.
  • High Bus Width and Throughput: Dedicated GPU memory buses are engineered specifically for high parallel throughput, often utilizing 64-bit, 128-bit, or wider dedicated buses running at higher clock frequencies than standard system LPDDR memory.
  • Interconnect Overhead: Data must be explicitly transferred between the host system memory and the GPU VRAM across the host interface (typically PCIe x1, x4, or x8 lanes on SBCs). This introduces communication latency for data synchronization.
  • Resource Isolation: Memory operations on the GPU do not consume host RAM bandwidth, preventing compute-intensive graphical workloads from throttling CPU performance.

Key Architectural Differences

Feature Unified Memory (UMA) Discrete GPU Memory (dGPU)
Physical Pool Shared with host CPU Dedicated VRAM pool
Interconnect Type Internal SoC crossbar/NoC Dedicated memory bus + PCIe host link
Bus Contention High (shared with CPU/I/O) None (isolated memory bus)
Data Transfers Zero-copy pointer sharing DMA copies across PCIe bus
Power & Space Low power, compact layout Higher power, requires additional PCB area
Memory Latency Low latency to system RAM High bandwidth, higher PCIe transfer latency

Summary of Trade-offs

Unified memory architectures provide compact, power-efficient designs ideal for size-constrained SBCs, avoiding data duplication at the cost of shared memory bandwidth. Conversely, discrete GPU memory architectures offer superior sustained throughput and isolate graphical workloads from system memory, but introduce PCIe transfer latency, higher thermal dissipation, and increased board complexity.
