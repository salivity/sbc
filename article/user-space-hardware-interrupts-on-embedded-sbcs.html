User Space Hardware Interrupts on Embedded SBCs

Handling hardware interrupts directly within user-space applications on embedded single board computers (SBCs) allows developers to bypass complex custom kernel module development while maintaining responsive systems. This guide details the standard kernel-provided interfaces—such as the Userspace I/O (UIO) framework, the modern Linux GPIO character device (gpio-cdev), and VFIO—along with core system-level tuning strategies to minimize latency, eliminate busy-waiting, and achieve efficient interrupt handling in user space.

Userspace I/O (UIO) Framework

The Linux Userspace I/O (UIO) framework is the standard mechanism for handling device interrupts in user space. UIO drivers in the kernel handle only the bare minimum: enabling the hardware clock, registering the interrupt line, and acknowledging the hardware interrupt.

  1. Kernel Side (uio_pdrv_genirq): A small generic driver binds to the peripheral's device tree node and creates a character device under /dev/uioX.
  2. User Space Interface: The application opens /dev/uioX and issues a blocking read() or uses poll()/epoll().
  3. Interrupt Acknowledgment: When an interrupt occurs, the kernel unblocks the user-space process. The application reads a 4-byte integer representing the interrupt count, processes the event, and writes a 1 back to /dev/uioX to re-enable the interrupt line.
int fd = open("/dev/uio0", O_RDWR);
uint32_t info = 1; /* Re-enable interrupts */

while (running) {
    uint32_t count;
    // Blocks until the hardware interrupt fires
    read(fd, &count, sizeof(count));
    
    // Process hardware event here
    
    // Re-enable the interrupt line
    write(fd, &info, sizeof(info));
}

Linux GPIO Character Device (gpio-cdev / libgpiod)

For SBCs where interrupts are triggered by external pins, the legacy sysfs interface (/sys/class/gpio) has been replaced by the high-performance GPIO character device ABI (/dev/gpiochipX), accessed via libgpiod.

  • Event Detection: You request an edge event (rising, falling, or both) on a line.
  • Non-blocking Event Loop: The character device provides a file descriptor compatible with epoll(), allowing an event loop to wait for hardware edges without CPU spinning.
  • Timestamping: The kernel provides hardware or interrupt timestamps with each event packet, reducing timing jitter caused by user-space context switching.

VFIO (Virtual Function I/O)

For high-performance peripherals on advanced SBCs featuring an IOMMU (Input-Output Memory Management Unit), VFIO offers a secure and direct user-space driver environment. VFIO provides:

  • Direct register access via mmap().
  • Direct DMA mapping without kernel mediation.
  • Interrupt delivery to user space using eventfd descriptors, which integrate natively with event loops.

Optimizing User-Space Interrupt Latency

To achieve deterministic and low-latency performance in user space, standard Linux OS configurations must be adjusted:

1. Thread Scheduling and Real-Time Priorities

Set the user-space interrupt handling thread to a real-time scheduling policy such as SCHED_FIFO or SCHED_RR with high priority.

struct sched_param param;
param.sched_priority = 80;
pthread_setschedparam(pthread_self(), SCHED_FIFO, &param);

2. Memory Locking (mlockall)

Page faults introduce significant, unpredictable latency. Lock the entire address space of the process into RAM:

mlockall(MCL_CURRENT | MCL_FUTURE);

3. CPU Isolation and Affinity

Dedicate a specific CPU core exclusively to the user-space interrupt handler to avoid cache thrashing and context switching:

  • Boot the kernel with isolcpus=<core_id>.
  • Set the affinity of the interrupt handling thread to the isolated core using pthread_setaffinity_np().
  • Direct hardware IRQs to other cores via /proc/irq/<irq_number>/smp_affinity.

4. Real-Time Kernel (PREEMPT_RT)

Applying the PREEMPT_RT patch transforms kernel interrupt handlers into preemptible threads, reducing the time user-space threads spend waiting for lower-priority kernel operations to complete.
