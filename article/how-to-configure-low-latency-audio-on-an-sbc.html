How to Configure Low-Latency Audio on an SBC

Configuring a low-latency audio stack on a multimedia Single Board Computer (SBC) requires optimizing the operating system, tuning the Advanced Linux Sound Architecture (ALSA), and configuring the JACK Audio Connection Kit for real-time processing. This guide outlines the essential steps to minimize audio buffer sizes, eliminate latency, and avoid audio dropouts (xruns) on resource-constrained hardware such as Raspberry Pi, BeagleBone, or Odroid boards.

1. System and Kernel Optimization

Achieving low-latency audio requires a kernel and OS environment tuned for real-time responsiveness.

  • Enable Real-Time Scheduling: Grant your audio user account real-time scheduling and memory locking privileges. Edit /etc/security/limits.d/audio.conf (or create it) and add: 
    @audio - rtprio 95
@audio - memlock unlimited
@audio - nice -19
    Ensure your user belongs to the audio group: 
    sudo usermod -a -G audio $USER
  • Set CPU Governor to Performance: Dynamic CPU scaling introduces latency spikes. Force all CPU cores to run at maximum clock speed: 
    echo "performance" | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor
  • Use a Real-Time (PREEMPT_RT) Kernel (Optional but Recommended): For latencies under 5ms, install a distribution kernel built with CONFIG_PREEMPT_RT enabled.

2. Direct ALSA Tuning

ALSA handles direct communication with your audio hardware. To bypass software mixing layers like PulseAudio or PipeWire for dedicated low-latency pipelines:

  1. Identify your hardware card and device numbers: 
    aplay -l
  2. Route audio directly through the hardware device identifier (e.g., hw:0,0 or hw:AudioDevice) rather than software abstractions (default or plug:default). This bypasses the ALSA dmix plugin, reducing processing overhead.

3. Configuring the JACK Audio Connection Kit

JACK operates on top of ALSA to provide deterministic real-time audio routing between applications.

Installation

Install JACK2 alongside command-line utilities:

sudo apt-get update
sudo apt-get install jackd2

When prompted during installation, select Yes to enable real-time priority.

Launching JACK with Low-Latency Parameters

Run jackd headless or from a system service using the following parameters:

jackd -R -P 90 -d alsa -d hw:CARD -r 48000 -p 64 -n 2

Parameter Breakdown:

  • -R: Enables real-time mode.
  • -P 90: Sets real-time priority (must match or be lower than limits in audio.conf).
  • -d alsa: Selects the ALSA driver backend.
  • -d hw:CARD: Points directly to the audio hardware card name or index.
  • -r 48000: Sets the sample rate to 48 kHz (standard for low-latency digital audio).
  • -p 64: Sets the buffer size (frames per period). Lower values reduce latency (e.g., 64 frames = ~1.33 ms at 48 kHz).
  • -n 2: Sets the number of periods in the buffer (2 is standard for internal/PCI/I2S devices; 3 is recommended for USB interfaces).

4. Monitoring and Verifying Latency

Total round-trip hardware buffer latency (\(L\)) is calculated as: \[L = \frac{p \times n}{r}\]

For a setup with \(p = 64\), \(n = 2\), and \(r = 48000\), the algorithmic buffer latency is approximately 2.67 ms.

To verify system stability:

  • Monitor the terminal output of jackd for xrun notices (buffer overruns/underruns).
  • If xruns occur, gradually increase the period size (-p 128 or -p 256) or increase periods to -n 3 until the stream is stable.
