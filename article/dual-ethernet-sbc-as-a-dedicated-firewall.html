Dual-Ethernet SBC as a Dedicated Firewall

A dual-Ethernet single board computer (SBC) functions as a dedicated network firewall by physically separating local and external networks, controlling data flow through kernel-level packet inspection, and utilizing specialized routing software. By positioning two distinct physical network interface controllers (NICs) between an internal local area network (LAN) and an external wide area network (WAN), the SBC serves as a secure gateway that filters malicious traffic, manages IP address assignments, and enforces security policies in real time.

Physical Interface Segregation (WAN and LAN)

The primary requirement for an inline hardware firewall is physical network isolation. A dual-Ethernet SBC provides two independent physical network interfaces:

  • WAN Port (Ingress/Egress to Internet): Connects to the modem or upstream internet service provider. This interface receives untrusted incoming traffic and sends outbound requests.
  • LAN Port (Internal Network): Connects to an internal network switch or access point, managing traffic from trusted local devices.

Because these interfaces operate on separate physical buses or PCIe lanes, traffic cannot bypass the SBC's processor and operating system, ensuring that all data packets undergo inspection before crossing from one network to the other.

Kernel-Level Packet Filtering Engines

The core security mechanism of a dual-Ethernet SBC is its kernel packet filtering framework, such as Netfilter (nftables/iptables) on Linux or pf (Packet Filter) on BSD systems.

When a packet arrives at the WAN or LAN interface:

  1. Prerouting: The kernel intercepts the packet before making a routing decision.
  2. Rule Evaluation: The firewall compares the packet’s headers (source IP, destination IP, port numbers, protocols) against predefined access control lists (ACLs).
  3. Action Execution: The engine takes immediate action—such as ACCEPT, DROP, REJECT, or LOG—preventing unauthorized ingress or egress.

Stateful Packet Inspection (SPI)

Modern firewalls rely on stateful inspection rather than simple static filtering. Using connection tracking subsystems (such as Linux conntrack), the SBC monitors the state of active network connections (e.g., NEW, ESTABLISHED, RELATED, or INVALID).

  • Outbound Requests: When an internal device requests a webpage, the SBC records the outgoing connection parameters.
  • Inbound Responses: Returning packets from the internet are matched against the established connection table. If matched, they are permitted through to the LAN.
  • Unsolicited Inbound Traffic: External connection attempts not associated with an existing state entry are dropped automatically.

Network Address Translation (NAT) and Routing

The SBC enables Linux kernel IP forwarding (ip_forward) to bridge the two interfaces while deploying Network Address Translation (NAT):

  • Source NAT (Masquerading): Hides internal private IP addresses (such as 192.168.1.0/24) behind a single public or upstream IP address assigned to the WAN port.
  • Destination NAT (Port Forwarding): Selectively directs inbound traffic on specific ports to designated internal servers while shielding the rest of the private network.
  • DHCP and DNS Services: Integrated software daemons (like dnsmasq or Unbound) assign IP addresses to LAN clients and resolve domain names, allowing the SBC to act as the complete default gateway for the network.

Firewall Operating Systems and Control Planes

Specialized open-source operating systems turn low-power SBC hardware into fully configurable appliances. Distributions such as OpenWrt, pfSense, or OPNsense provide a streamlined user interface to configure routing policies, intrusion prevention systems (IPS), virtual private networks (VPNs via WireGuard or OpenVPN), and real-time network monitoring without requiring manual low-level command-line configuration.
